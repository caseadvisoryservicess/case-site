# Как посадить платформу на хостинг — детальная инструкция

Цель: лендинг на `caseadvisory.uz/taxtapul`, админ-панель с CRM на
`caseadvisory.uz/admin` (или `panel.caseadvisory.uz`), кнопка «Войти» на
лендинге ведёт в панель, заявки падают в CRM и на почту.

---

## Шаг 0. Определите, какой у вас хостинг (2 минуты)

Панель — это программа на Node.js, ей нужен **VPS** (виртуальный сервер).
Сам лендинг — обычные файлы, ему хватает любого хостинга.

Узнайте, где сейчас живёт caseadvisory.uz. Признаки:

| Если… | То у вас | Ваш путь |
|---|---|---|
| Вы заходите на сервер по SSH, есть root-доступ | **VPS** | Путь 1 — всё на одном сервере |
| Панель управления cPanel / ISPmanager / Plesk, «файловый менеджер», только PHP | **виртуальный хостинг** | Путь 2 — лендинг там, панель отдельно |
| Не знаете | спросите поддержку хостинга: «есть ли у меня SSH и root, можно ли запустить Node.js-приложение?» | по ответу — Путь 1 или 2 |

---

## Путь 1. У вас VPS (или вы его купите) — всё на одном сервере ★ рекомендую

Подойдёт VPS от 1 ГБ RAM с Ubuntu 22.04/24.04: ahost.uz, cloud.timeweb, beget
VPS, DigitalOcean — от ~$4–6/мес. При заказе выберите образ **Ubuntu 22.04**,
вы получите **IP-адрес** и **root-пароль** на почту.

### 1.1. Подключитесь к серверу

Windows 10/11: откройте PowerShell. Mac: Терминал. Введите:

```bash
ssh root@ВАШ-IP
# на вопрос "Are you sure you want to continue connecting?" → yes
# введите root-пароль (при вводе символы не видны — это нормально)
```

Вы «внутри» сервера, приглашение сменилось на `root@...:~#`.

### 1.2. Установите платформу (копируйте блоками)

```bash
apt update && apt install -y git
git clone https://github.com/caseadvisoryservicess/case-site.git /opt/case-site
cd /opt/case-site/admin
bash deploy/install-vps.sh
```

Скрипт сам поставит Node.js, зависимости и настроит автозапуск. В конце
напишет: `Панель: http://ВАШ-IP:3000`. Проверьте: откройте этот адрес в
браузере — должна открыться форма входа (admin / admin). Если открылась —
основное готово.

> Репозиторий приватный? Тогда вместо git clone: залейте архив
> `sfb-platforma.zip` на сервер командой с ВАШЕГО компьютера:
> `scp sfb-platforma.zip root@ВАШ-IP:/opt/` затем на сервере:
> `cd /opt && apt install -y unzip && unzip sfb-platforma.zip && mv sfb-platforma /opt/case-site-admin && cd /opt/case-site-admin && bash deploy/install-vps.sh`

### 1.3. Направьте домен на сервер

В панели, где вы управляете DNS домена caseadvisory.uz (обычно сайт
регистратора, например ahost/webspace):

- если ВЕСЬ сайт переезжает на этот VPS: измените **A-запись** `@` (и `www`)
  на ВАШ-IP;
- если основной сайт остаётся где был, а сюда — только панель: создайте
  **A-запись** `panel` → ВАШ-IP (получится panel.caseadvisory.uz, а лендинг
  кладите по Пути 2).

DNS обновляется от 15 минут до пары часов.

### 1.4. Nginx: красивые адреса и HTTPS

```bash
apt install -y nginx certbot python3-certbot-nginx
cp /opt/case-site/admin/deploy/nginx.conf.example /etc/nginx/sites-available/sfb-panel
nano /etc/nginx/sites-available/sfb-panel
```

В открывшемся файле замените (внутри всё подписано комментариями):
- `caseadvisory.uz www.caseadvisory.uz` → ваш домен (или panel.caseadvisory.uz);
- путь `alias /opt/case-site/admin/sites/takhtapul/;` — оставьте как есть,
  если ставили через git clone.

Сохранить: `Ctrl+O`, Enter. Выйти: `Ctrl+X`. Дальше:

```bash
ln -s /etc/nginx/sites-available/sfb-panel /etc/nginx/sites-enabled/
nginx -t                     # должно ответить: syntax is ok / test is successful
systemctl reload nginx
certbot --nginx              # выбрать домен(ы), согласиться — HTTPS готов
```

### 1.5. Проверка

- `https://caseadvisory.uz/taxtapul/` — лендинг открывается;
- кнопка **«Войти»** в шапке → `…/admin/` → вход admin/admin работает;
- отправьте тестовую заявку с лендинга → она появилась в разделе «Лиды».

Всё. Дальше — чек-лист первого включения из ИНСТРУКЦИЯ.md (сменить пароль,
агенты, почты, SEO-коды).

### Обновление платформы в будущем

```bash
ssh root@ВАШ-IP
cd /opt/case-site && git pull && cd admin && npm ci --omit=dev && systemctl restart sfb-panel
```

## Путь 2. caseadvisory.uz — виртуальный хостинг (cPanel, без Node)

Лендинг остаётся на вашем хостинге, панель живёт отдельно.

### 2.1. Лендинг на ваш хостинг

1. Возьмите файл **taxtapul-landing.zip**.
2. В панели хостинга откройте **Файловый менеджер** → папку сайта
   (обычно `public_html`).
3. Создайте папку **taxtapul** → зайдите в неё → **Загрузить** zip →
   правой кнопкой → **Extract/Распаковать** (файлы index.html, robots.txt и
   папка assets должны оказаться прямо в /taxtapul, без вложенной папки —
   если вложилась папка takhtapul, перенесите её содержимое на уровень выше).
4. Проверьте: `https://caseadvisory.uz/taxtapul/` открывается.

### 2.2. Панель — на Render.com (без своего сервера)

1. https://render.com → регистрация через GitHub.
2. **New + → Blueprint** → выберите репозиторий `caseadvisoryservicess/case-site`
   → Render прочитает готовый `render.yaml`.
3. Введите `ADMIN_PASSWORD` (ваш будущий пароль администратора) → **Apply**.
4. Через 2–3 минуты панель доступна по адресу вида
   `https://sfb-panel.onrender.com` (запишите его).
5. Красивый адрес (по желанию): в Render → Settings → **Custom Domains** →
   добавьте `panel.caseadvisory.uz`; у регистратора домена создайте
   **CNAME-запись** `panel` → значение, которое покажет Render.

(Вместо Render можно купить самый дешёвый VPS и пройти Путь 1 только для
панели — тогда домен panel.caseadvisory.uz указываете A-записью на его IP.)

### 2.3. Связать лендинг с панелью

В панели откройте проект Тахтапул → вкладка «Основное»:

- **Кнопка «Войти» на лендинге** → `https://sfb-panel.onrender.com`
  (или https://panel.caseadvisory.uz);
- **Приём заявок (URL)** → `https://sfb-panel.onrender.com/api/lead/takhtapul` —
  тогда заявки с лендинга на вашем хостинге полетят в CRM панели
  (междоменные запросы уже разрешены);
- «Сохранить и собрать» → **«Скачать сайт (zip)»** → перезалейте файлы в
  папку /taxtapul на хостинге (как в 2.1).

Да, при каждом редактировании лендинга по Пути 2 нужно перезаливать zip —
это цена виртуального хостинга. На Пути 1 всё обновляется кнопкой.

## Путь 3. Вообще без своего хостинга (самый быстрый старт)

Просто выполните пункт 2.2 (Render). Лендинг будет жить по адресу
`https://sfb-panel.onrender.com/p/takhtapul/` — его уже можно давать в
рекламу, форма и CRM работают сразу, ничего перезаливать не надо.
Свой домен добавите позже через Custom Domains.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `http://IP:3000` не открывается | подождите минуту; на сервере: `systemctl status sfb-panel` — должно быть active (running); файрвол хостера — откройте порт 3000 или сразу настройте nginx (порт 80/443) |
| nginx -t ругается | опечатка в файле — проверьте строки, которые меняли; каждая строка заканчивается `;` |
| Домен не открывается | DNS ещё не обновился (до 2 часов); проверьте A-запись на сайте dnschecker.org |
| Лендинг открылся, но без картинок | файлы распакованы во вложенную папку — index.html должен лежать прямо в /taxtapul рядом с папкой assets |
| Заявка не появляется в «Лидах» | Путь 2: проверьте, что в «Приём заявок (URL)» полный адрес с /api/lead/takhtapul и что после этого лендинг пересобран и перезалит |
| Письма о лидах не приходят | нажмите кнопку подтверждения в первом письме от FormSubmit (приходит на каждый новый адрес один раз); проверьте «Спам» |
| Забыли пароль админа | на сервере: `rm /opt/case-site/admin/data/users.json && systemctl restart sfb-panel` — создастся admin/admin заново (агентов придётся завести снова) |

## Бэкап (обязательно раз в неделю)

Вся ценность — папка `admin/data/` (проекты, фото, пользователи, лиды).

```bash
# с вашего компьютера, копия сервера себе:
scp -r root@ВАШ-IP:/opt/case-site/admin/data ./backup-$(date +%F)
```

На Render данные лежат на подключённом диске и переживают деплои, но
скачивать копию через «Скачать сайт (zip)» + экспорт тоже полезно.
