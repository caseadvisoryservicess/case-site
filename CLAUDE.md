# CASE Real Estate Advisory - панель и лендинг Taxtapul

Паспорт проекта. Читай целиком перед началом работы: здесь состояние, правила и процессы, наработанные за все прошлые сессии.

## Что это

Мультиарендная платформа лендингов «Панель CASE» (Node/Express + vanilla JS) для компании CASE Real Estate Advisory (caseadvisory.uz). Главный проект: лендинг коммерческого здания TAXTAPUL, ул. Тахтапул 31, Ташкент. Продакшен живёт на shared-хостинге cPanel (Phusion Passenger), лендинг опубликован на https://caseadvisory.uz/taxtapul/ (+ /uz/ и /en/). Всё работает и проверено владельцем.

## Жёсткие правила (нарушать нельзя)

1. НИКОГДА не использовать длинные тире (em/en dash). Только короткий дефис. Это касается кода, текстов лендинга, PDF и даже сообщений в чате. Оба генератора уже делают глобальную замену `[—–] -> '-'` на выходе, не удаляй её.
2. Никаких цен и сроков завершения строительства ни в каком виде.
3. Никаких выдуманных цифр. Только проверенные: таблица GBA/GLA/отметок этажей и потолки из разреза (все уже в admin/data/projects/takhtapul/project.json и в scripts/gen-presentation.js).
4. Название SFB НЕ упоминается нигде. (Историю знать полезно: сначала было согласовано ровно одно упоминание в «О зданиях», но 2026-07-24 владелец решил убрать SFB полностью - миграции 006 и 007, шаблон скрывает пустую строку sfbNote.)
5. Формулировка статуса стройки и тексты сценариев сделки согласованы дословно, менять без запроса владельца нельзя.
6. Канонические URL: https://caseadvisory.uz/taxtapul/ (+uz/, en/). Слаг проекта в панели: takhtapul, папка на проде: taxtapul. Не путать.
7. Данные продакшена (project.json с SMTP/Telegram секретами, лиды, аналитика) НИКОГДА не перезаписываются деплоем. Код деплоится отдельно, данные меняются только миграциями или через панель.
8. Общение с владельцем на русском. Он не программист: инструкции давать пошагово, по одной команде.

## Структура репозитория

- admin/ - вся система (Express 5, BASE_PATH=/admin, роутер под Passenger)
  - server.js - API: генерация лендинга, лиды, аналитика (POST /api/e/:slug, NDJSON), бэкап
  - lib/template2.js - SSR-генератор лендинга v2: три языковые страницы (ru корень, uz/, en/), hreflang, JSON-LD, sitemap. Главный файл лендинга
  - lib/images.js - пайплайн изображений: jimp + @jsquash/webp (WASM), варианты 640/1280/1920 JPEG+WebP
  - scripts/gen-presentation.js - генератор PDF-презентаций на трёх языках (Playwright Chromium, A4 landscape): presentation.pdf, presentation-uz.pdf, presentation-en.pdf
  - public/app.js, style.css - SPA админки (вкладки v2, страница «Аналитика», лиды с воронкой)
  - migrations/ - аддитивные обратимые миграции (001-schema-v2, 002-texts)
  - data/projects/takhtapul/ - конфиг и загрузки локальной копии проекта (у прода свои данные)
- .claude/skills/ui-ux-pro-max/ - установленный скилл: база UI/UX-стилей, палитр, шрифтов; поиск: `python3 .claude/skills/ui-ux-pro-max/scripts/search.py "запрос" --domain style`
- .mcp.json - MCP-сервер Magic (21st.dev), ключ в переменной окружения MAGIC_21ST_API_KEY

## Продакшен и деплой (владелец делает руками, ты готовишь zip)

Хостинг: cPanel, приложение в /home/wwwcasea/admin_panel, node_modules это симлинк на /home/wwwcasea/nodevenv/admin_panel/22/lib/node_modules (CloudLinux Selector). npm на хосте падает по памяти, зависимости шлём готовым zip (все pure-JS). Playwright на проде берётся из /opt/node22/lib/node_modules/playwright (fallback в скриптах).

ВАЖНО (выяснено при установке update-13): «Сохранить и собрать» отправляет на сервер ВЕСЬ конфиг из открытой вкладки панели. Если вкладка была открыта до миграций, она затрёт их изменения старыми данными. Порядок всегда такой: миграции в терминале -> F5 в админке -> «Сохранить и собрать». Команда node на проде доступна только через окружение приложения (пути /opt/node22/bin/node НЕТ):
`source /home/wwwcasea/nodevenv/admin_panel/22/bin/activate && cd /home/wwwcasea/admin_panel && node migrations/00N-... .js`

Стандартный цикл обновления:
1. Собрать zip только с изменёнными файлами: `taxtapul-update-N.zip` (нумерация сквозная, последний был 15), отправить владельцу через SendUserFile.
2. Инструкция владельцу: File Manager -> загрузить zip в admin_panel -> Extract с заменой -> Setup Node.js App -> «Перезапустить приложение» -> в админке «Сохранить и собрать» -> в терминале:
   `rm -rf /home/wwwcasea/public_html/taxtapul/* && cp -r /home/wwwcasea/admin_panel/sites/takhtapul/. /home/wwwcasea/public_html/taxtapul/ && echo ГОТОВО`
3. Владелец проверяет и присылает скриншоты. Прод из этой среды напрямую недоступен (egress закрыт), верификация только через владельца.

## Аналитика (первая сторона, работает на проде)

Клиент батчит события через sendBeacon в POST /api/e/:slug (без CSRF), сервер пишет NDJSON в data/analytics/<slug>/events-YYYY-MM-DD.ndjson. События: page_view, scroll_depth, unit_click, plan_view, plan_download, pdf_download, cta_*, form_start/submit/success, map_open, faq_open, intent_switch. В админке страница «Аналитика»: выбор проекта или «все», периоды, источники, устройства, воронка visit->form по интентам lease/buy, интерес к юнитам, печать PDF-отчёта. Не ломать формат событий: копится история.
