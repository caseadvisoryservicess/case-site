# CASE OS · Leasing & Sales Platform (LSP) — validation prototype v0.1.0

Один файл: `os/leasing/index.html`. Открывается двойным щелчком с диска и работает
на хостинге по адресу `caseadvisory.uz/os/leasing/` после обычной заливки папки `os`.
Ничего не устанавливается, интернет не нужен, внешних библиотек нет.

## Что это

Прототип операционной системы отдела аренды и продаж: CRM, база проектов и помещений,
интерактивные планировки, воронки аренды и продаж, база брендов, задачи, документы,
портал собственника, отчёты и локальное хранение. Проверочная версия для обкатки
процесса командой — **не продуктивная система**.

## С чего начать (5 минут)

1. Откройте `index.html`.
2. Выберите демо-пользователя и нажмите **Enter** (пароля нет — это прототип).
   Двойной щелчок по карточке пользователя тоже входит.
3. **Планировка** → щёлкните помещение → откроется карточка: статус, бренды-претенденты,
   сделки, подсказки по брендам, история.
4. Смените статус в карточке — цвет на плане, дашборд, воронка и отчёт пересчитаются сразу.
5. **Воронка аренды** → перетащите карточку между этапами (история этапа записывается).
6. Выйдите и войдите как **Demo Owner (City Mall)** — увидите портал собственника:
   только его проект, без комиссий, без внутренних заметок.
7. **Отчёты → Client report → Печать** — отчёт собирается из текущих данных.

## Что важно знать

- **Данные живут только в этом браузере** (`localStorage`). Другой браузер или другой
  компьютер — другие данные. Резервная копия: **Импорт / Экспорт → Full backup (JSON)**.
- **Демо-данные вымышленные.** Проекты, бренды, компании и контакты придуманы.
  Реальные клиенты CASE и реальная база брендов сюда не переносились.
- **Это не защита.** Вход без пароля, ролевое разделение — только в интерфейсе.
  Продуктивная версия требует сервера, авторизации и защищённого хранения файлов.
- **Файлы не хранятся.** Реестр документов записывает только карточку файла.
- Сброс: **Импорт / Экспорт → Reset to demo data** или кнопка на экране входа.

## Правила, на которых держится модель

1. **Статус помещения — это состояние инвентаря, этап — это сделка.** На плане
   показывается производная: свободное помещение с живой сделкой показывает этап.
2. **Площадь помещения считается один раз.** Три претендента на одно помещение не
   утраивают GLA. Метрики воронки считаются по сделкам и прямо помечены как таковые.
3. **Неизвестное не равно нулю.** Помещение без площади исключается из сумм и
   показывается отдельной строкой «n units without area».
