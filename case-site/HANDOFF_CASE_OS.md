## 2. Что это за проект

CASE OS — операционная система для агентства недвижимости (аренда/продажи/advisory/гео-аналитика).
Архитектура:
- **Фронтенд:** один большой файл `os/index.html` (APP_VERSION, все основные экраны) + отложенные JS-модули `os/v*.js` (например `v35-stable.js` = База брендов, `v32-upgrade.js` = SCR-продажи, `v410-feature-flags.js` = управление модулями, `v417-master-plan.js` = мастер-планировки, `v420-geo-*` = гео).
- **Бэкенд:** PHP в `os/api/*.php` + MySQL. Ключевые: `lib.php` (ядро, права, таблицы), `state.php` (общий blob состояния), `users.php`, `data.php` (generic CRUD).
- **PWA:** `os/sw.js` (network-first, кэш `case-os-vNNNNN`).
- Режимы: **backend** (есть `os/api/config.php` + MySQL) или **demo** (только `?demo=1`, данные в localStorage).

## 3. Как это развёрнуто (ВАЖНО — источник всех «ничего не меняется»)

- Живой сайт: **`https://caseadvisory.uz/os/`** на хостинге **DirectAdmin** (`caseadvisory.uz:2222`, логин `wwwcasea`). Домен `.com` — другой сервер, туда файлы класть бесполезно.
- **Автодеплоя из GitHub нет** (пользователь не хочет зависеть от GitHub). Обновление = вручную загрузить ZIP в `domains/caseadvisory.uz/public_html/` через Менеджер файлов → Extract с перезаписью `os/`.
- Поэтому: коммит/ZIP сами по себе НЕ меняют живой сайт. Обязательно проверять номер версии вверху страницы (`v4.31.xx`) после загрузки.
- Каждый релиз собирать как **`CASE_OS_vX_os_only.zip`** (только папка `os/`, БЕЗ `config.php` — чтобы не затирать доступ к БД и не трогать лендинг).

## 7. Что осталось (из аудита v4.31.18) — приоритет для новой сессии

- **P0-1 (критично, архитектура):** версия планировки не привязана к реальному чертежу. Генерация LCR всегда читает глобальный `PLAN_CODES`; переключение версии меняет только метку. Нужно: у каждой версии — неизменяемый snapshot (SVG + `PLAN_CODES` + блоки/этажи + контрольная сумма + автор/дата), и генерировать LCR строго из выбранного snapshot. Затрагивает `os/v417-master-plan.js` + генерацию LCR в `os/index.html`. Это ядро — тестировать VM-тестами, аккуратно (риск для реальных данных по арендам).
- **P1-1:** коммерческая защита юнита должна быть project-scoped (ключ `projectId+unitId`, а не только код помещения).
- **P1-2:** убрать массовый override защищённых площадей (`overrideProtected`), заменить на per-unit workflow с причиной и audit.
- **P1-3:** объединить/перенаправить три параллельных маршрута планировок (`plans`, `project_layouts`/`leasing_layouts`, `plan_master`) в единый master.
- **P1-5:** единый registry модулей (клиент `CASE_OS_MODULES` ↔ `validViews` ↔ серверный список). Расхождения: `admin_modules`/`admin_system`/`v32_demand` не в `validViews`; `chat` не в каталоге; `analytics_hub` не на сервере.
- **P1-6:** сохранение — перейти к patch/доменным ревизиям + diff/merge вместо глобального revision + 409.
- **P2:** обновить хвостовые метки версий (footer/SW-комментарий `v4.17.0`, `?v=4.17.0` в 16 script-URL, `DEPLOY.md` v4.10.0); добавить CHANGELOG/checksum текущего релиза; убрать пустые `.sha256`; рассмотреть CSP/HSTS.
