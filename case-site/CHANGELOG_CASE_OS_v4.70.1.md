# CASE OS v4.70.1

Патч безопасности. Только права доступа к финансовым полям помещений, без изменения
бизнес-данных и без переделки интерфейса - как и рекомендовал независимый аудит v4.70.0.

## Что было не так

Независимый аудит нашёл две проблемы уровня P0. Обе подтвердились при проверке по коду.

**Маскировка на экране защитой не была.** Роли без права finance (агент аренды, архитектор)
видели в реестре ставки как `•••`, но сервер отдавал настоящие цифры тремя путями сразу:

- `api/state.php` возвращал ключ `U` со всеми полями: `redact_shared_state()` чистил восемь
  других ключей, а помещения не трогал вовсе;
- выгрузка CSV в `core.js` проверяла право finance только для двух столбцов из четырёх -
  «Ставка $/м²» и «Бюджет $/м²» уходили в файл всегда;
- ответ `unit_patch.php` возвращал помещение целиком.

Значение, скрытое только на экране, доступно через выгрузку, инструменты разработчика и
прямой запрос к API. Это утечка на сервере, а не дефект интерфейса.

**Агент аренды мог менять цену и состав объекта.** Право `edit` открывало ему:

- `unit_patch.php` принимал `rate`, `budget`, `budLand`, `factLand`, `capex`, `total`, `gap`
  без единой проверки на finance;
- `units_batch.php` разрешал массовый upsert и удаление помещений любому с `edit`.

По описанию роли агент ведёт показы, брони и свои KPI. Фактически он мог переписать ставки,
удалить помещения и залить реестр целиком.

## Что сделано

**Один список финансовых полей на всю систему.** `lib.php` - единственное место, где они
перечислены: `unit_finance_fields()`. Все три серверных пути спрашивают его, а не держат
свой список, иначе расхождение вернётся при первом же добавленном поле. Площадь и терраса в
список намеренно не входят: архитектору они нужны для работы и коммерческой тайной не
являются. Скрываем деньги, а не геометрию.

| Путь | Что изменилось |
|---|---|
| `state.php` GET | деньги вырезаются из `U` для ролей без finance |
| `state.php` POST | деньги восстанавливаются из серверной копии по идентификатору |
| `unit_patch.php` | финансовые поля отклоняются и отказ возвращается в `blocked_fields` |
| `unit_patch.php` ответ | отданное помещение тоже чистится |
| `units_batch.php` | массовые операции требуют права на финансы или планировки |
| `core.js` выгрузка | финансовые столбцы отсутствуют, а не пустуют |
| `core.js` панель | «Импорт CSV», «Блоки из кодов», «GLA из юнитов» скрыты без права |

**Поля удаляются, а не обнуляются.** Подставленный ноль выглядел бы как настоящая бесплатная
ставка. Клиент должен отличать «поля нет» от «поле равно нулю».

**Самое важное: защита не стала потерей данных.** Роль без finance получает помещения без
денег и сохраняет весь state целиком. Приняв такое сохранение как есть, система стёрла бы
ставки у всех. Поэтому финансовые поля каждого помещения берутся из серверной копии по
идентификатору, а присланные клиентом отбрасываются. Утечку заметят, молчаливую пропажу
ставок - нет, поэтому это свойство проверяется отдельно и первым.

**Отказ слышен.** Молча выбросив поле, система показала бы «сохранено» там, где ничего не
сохранилось, и пользователь узнал бы об этом на переговорах с арендатором.

## Проверка

`docs/qa/tools/v4701_unit_finance_acl.php` - 57 проверок по всем десяти ролям:

- кто видит деньги, а кто нет, по каждому полю;
- кто может менять состав помещений;
- сохранение агентом не теряет и не меняет ни одного финансового поля;
- подложенная агентом ставка отбрасывается;
- новому помещению агент не может назначить цену, но само помещение создаётся;
- роль с правом finance работает свободно;
- все три пути принимают решение общей функцией, а не своим списком.

Регресс против v4.70.0 полный: ролевой доступ в браузере, обход всех разделов, конфликты
CSS, унификация воронок, сквозная симуляция предложения, инварианты релиза - все зелёные.

## Чего этот патч НЕ делает

Аудит предлагал ввести пятнадцать отдельных прав на действия с помещением
(`unit.financial_edit`, `unit.structure_edit` и другие). Здесь этого нет намеренно: патч
закрывает утечку минимальным изменением и не переписывает модель прав. Granular permissions
и Access Center - отдельная работа, и смешивать её с патчем безопасности не стоит.

Не закрыты и остальные находки аудита: настройки геостудии под ключом `guest`, ложное
предупреждение `server_check.php`, длина правильного ответа в тесте знаний, состав архива,
плавающая кнопка чата на мобильном. Они не про безопасность и идут следующим патчем.
