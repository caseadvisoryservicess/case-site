# CASE OS v4.72.0

Гео-ассистент в студии геоаналитики. Клиент задаёт участок и просит словами: «радиус 1 км и
население», «покажи здания и дороги», «выдели дома выше 9 этажей», «сделай здания синими».
Так работают ассистенты Aino World и Placer.ai. Отличие CASE одно, и оно принципиальное.

## Модель пишет текст, но не выдумывает число

Ассистент Aino отвечает «в радиусе 1 км живёт 48 000 человек», и никто не знает, откуда
цифра. Здесь население, число зданий, километры дорог считают детерминированные
инструменты по данным, у которых есть происхождение: источник, метод, дата, уверенность.
Модель лишь выбирает инструмент и пересказывает результат. Каждая цифра приходит с плашкой
происхождения - той же азбукой, что появилась в v4.71.0 у ставок и площадей: ✓ проверено,
≈ наблюдение, ƒ расчёт.

Это не украшение. Именно это CASE показывает клиенту, когда тот спрашивает «откуда», и
именно этого нет у конкурентов (бриф, §4.3: данные у всех одинаковые, ответа «откуда это
число» нет ни у кого).

## Что умеет

Десять инструментов, исполняются в браузере:

| Команда | Инструмент | Откуда число | Уверенность |
|---|---|---|---|
| участок: проект из списка, клик по карте, координаты | `set_site` | | |
| «радиус 500 м и 1 км» | `draw_radius` | геометрия | |
| «за 10 минут на авто» | `draw_isochrone` | OSRM по дорогам OSM | расчёт |
| «население 1 км» | `count_population` | сетка H3 с калибровкой на Toshstat 01.01.2026 | расчёт, с примечанием |
| «здания 500 м» | `load_buildings` | OpenStreetMap через Overpass | наблюдение |
| «дороги 1 км», «только магистрали» | `load_roads` | OpenStreetMap через Overpass | наблюдение |
| «выдели дома выше 9 этажей», «только жилые» | `select_features` | из загруженного слоя | |
| «сделай здания синими», цветовые поля | `style_layer` | | |
| «конкуренты 2 км» | `count_competitors` | база БЦ CASE | наблюдение |
| «очистить» | `clear_layers` | | |

Два пути разбора команды. Локальный (regex, русский, английский, узбекский) не требует
ни ключа, ни сети и работает в демо. Модель (Claude через `api/assistant.php`) понимает
свободную речь, комбинирует инструменты и пишет короткий пересказ; инструменты всё равно
исполняются в браузере. Без ключа ассистент говорит об этом один раз и работает командами.

## Про население, честно

Сетка населения (Kontur H3, 6865 ячеек) в самих данных помечена как «методологический
слой, проверить источник». Студия калибрует её на официальное население районов, что
чинит суммы по районам, но не распределение внутри района. Поэтому число жителей всегда
идёт с уверенностью «расчёт», источником, методом и примечанием «для решения брать как
порядок величины».

Считаем по **доле площади ячейки внутри круга**, а не «центроид попал / не попал». Ячейка
около 0.7 км², круг 500 м - 0.8 км²; счёт по центроидам ошибался бы в разы. Площадь ячейки
оценивается по самой сетке (расстояние между соседями), а не константой. Тест на
шестиугольной решётке известной плотности: доли площади дают ошибку до 8%, центроиды
заметно хуже, и тест это различает.

## Что найдено попутно

**Зонд студии считал население по сырой сетке.** Клик по карте («отчёт по точке») должен
был калибровать сетку, но проверка стояла на `if(!POP)`, а `POP` непуст с самого старта
(сырая сетка). Калибровка запускалась только при включении тепловой карты. Без неё сумма
по городу завышена примерно вдвое. Исправлено: проверка по `CAL`. Ассистент калибрует
сетку сам в любом случае.

**Дорога без вершин в круге.** Длинный прямой проспект имеет вершины далеко за кругом и по
одним вершинам выпадал из выборки. Теперь учитывается расстояние от центра до отрезка.

**Замкнутый контур OSM повторяет первую вершину последней**, и среднее вершин смещалось к
ней. Центроид считается без повтора. Поймано тестом на квадрате 100 x 100 м.

**`\b` в JS-регулярках не видит кириллицу** без флага `u`: «500 м и 1 км» терял «500 м».
Границы слов заменены на явные просмотры.

## Архитектура и безопасность

- Ключ API лежит в `config.php` и никогда не уходит в браузер. Студия живёт в iframe и не
  имеет CSRF-токена, поэтому к `assistant.php` ходит родительское окно тем же `apiPOST`,
  что и всё остальное (мост в `v420-geoanalytics.js`).
- Сервер без состояния: клиент хранит переписку и присылает целиком. Значит любая её часть
  могла быть подделана в DevTools; сервер чистит роли, типы блоков и вызовы несуществующих
  инструментов, обрезает длину, отклоняет диалог не с реплики пользователя.
- Ограничение частоты: 40 ходов за 10 минут на сессию. Каждый ход стоит денег.
- Модель по умолчанию `claude-opus-5`, адаптивное мышление, стабильная подсказка
  кэшируется на стороне API (`cache_control`), изменчивый контекст (участок, проекты, язык)
  отдельным блоком, чтобы не ломать кэш.
- Вызывается сырым HTTP, а не официальным PHP SDK: SDK требует PHP 8.1 и composer, боевой
  сервер работает на PHP 7.2 и разворачивается копированием папки. Весь новый PHP-код
  проверен на отсутствие конструкций новее 7.2 автоматически.
- Здания и дороги: OpenStreetMap по ODbL, атрибуция возвращается в каждом ответе и видна в
  панели. Кэш на сервере 30 дней в существующей `gis_analysis_cache`. Данные 2GIS и Яндекса
  в эти слои не попадают: их условия запрещают хранение (бриф, §7).
- Различие плашек не только цветом (значок, рамка, слово): материалы печатаются.

## Чего в выпуске намеренно нет

- **Изохроны пешком и на транспорте** - маршрутизатор OSRM в студии умеет только автомобиль.
- **Население по WorldPop** как вторая модель - растр лежит на рабочей машине (бриф, §8.3);
  как только он передан, ассистент покажет диапазон из двух моделей, как это уже делает
  профиль проекта.
- **Сохранение слоёв ассистента** между сеансами - сначала обкатать, потом решать, что из
  этого стоит хранить в GEO_DATA.
- **Многоконтурные здания** (relation) - их мало, а разбор вдвое сложнее.

## Что увидит пользователь

В геоаналитике, под «Проектом», секция «Ассистент» с полем ввода и чипами-подсказками.
Без ключа всё работает командами; с ключом в `config.php` добавляется свободная речь.
Число жителей всегда с плашкой «ƒ расчёт» и подсказкой, откуда оно. Здания и дороги с
подписью «© OpenStreetMap contributors».
