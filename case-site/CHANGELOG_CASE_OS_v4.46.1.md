# CASE OS v4.46.1 — живая синхронизация без перерисовок (слияние с вашим v4.45.1)

Дата: 2026-07-25. В v4.46.1 влит ваш билд v4.45.1_FULL_HOSTING_READY: точечная
синхронизация вместо полной перерисовки экрана. Плюс найден и закрыт ещё один
скрытый сброс позиции, который проявлялся только на хостинге.

## Причина (как вы её описали — подтверждена)

Фоновая синхронизация каждые 20 секунд перерисовывала весь текущий экран, даже если
на сервере изменились данные другого раздела. Полный рендер сбрасывал вертикальную
и горизонтальную позиции таблиц. Плюс после сохранения карточки видимая таблица не
всегда получала команду обновить свою строку.

## Что взято из вашего v4.45.1 (целиком)

1. **Новый модуль `v4451-live-sync.js`**:
   - снимок интерфейса перед любой перерисовкой: позиция страницы, прокрутки всех
     таблиц, активный элемент и позиция курсора, раскрытые блоки;
   - восстановление с повторами (40/120/260/520 мс) — переживает отложенные рендеры;
   - карта соответствия «раздел → ключи данных»: чужое изменение (например, чат)
     больше НЕ перерисовывает ЛСР;
   - событие `caseos:entity-saved` для будущих модулей.
2. **Опрос сервера стал деликатным** (`pollServerState`):
   - сравнивает, какие именно ключи изменились, и перерисовывает только если
     изменение касается текущего раздела;
   - «Данные обновлены» показывается только при реальных изменениях.
3. **Опрос не вмешивается, пока пользователь занят** (`isUserBusy` расширен):
   открыта карточка · идёт ввод (фокус в поле) · открыто модальное окно · идёт
   серверное сохранение (`_saveBusy/_savePend`) · есть неотправленные правки
   (`_offlineDirty`) · была локальная правка младше 2,5 с (`_lastLocalMutationAt`).
   Гонка «локальная правка ↔ автообновление» закрыта.
4. **Сохранения карточек** (помещение, бренд, контакт бренда, объединение дублей)
   идут через live-sync: обновляется именно текущий раздел с восстановлением позиции.
   База брендов после сохранения обновляет только результаты (лёгкий ререндер
   `asaas35RefreshResults`, фильтры и фокус не трогаются).
5. **Гео-студия**: `refreshAll` запоминает и восстанавливает позицию страницы,
   горизонталь таблицы и прокрутку данных (`geoUiSnapshot`/`geoUiRestore`).

## Что добавлено сверх вашего билда

1. **Универсальный фолбэк в `entitySaved`**: в вашей версии сохранение юнита
   обновляло только ЛСР/планировки/дашборд/карту — теперь любой текущий раздел
   (даты, документы, канбан…) тоже обновляется сразу, с тем же восстановлением
   позиции; встроенные студии (гео/ТЭО) не перезагружаются.
2. **Найден скрытый сброс позиции, только на хостинге**: первый клик
   «✎ Редактировать помещение» тянул список сотрудников с сервера
   (`loadSrvUsers` для списка брокеров), и ответ **молча перерисовывал ЛСР за
   карточкой** — позиция таблицы обнулялась. В demo-режиме это не воспроизводилось,
   поэтому прежние тесты не ловили. Теперь: без изменений в данных экран не
   трогается вовсе, при изменениях — перерисовка с восстановлением позиции.
3. Сохранены все решения v4.46.0: отчёт собственнику, строгие права ролей,
   сессия 12 ч + дозаливка правок, серверные настройки таблиц.
