# CASE OS — установка с нуля (простая, пошаговая)

Если запутались с базой — сделаем чисто заново. 10 минут.
Нужен один новый файл: **`os/sql/install_all.sql`** (он создаёт базу + таблицы + роли сам).

---

## ШАГ 0. Запустить XAMPP
1. Открыть **XAMPP Control Panel**.
2. **Start** напротив **Apache** и **MySQL** (оба зелёные).

---

## ШАГ 1. Положить файлы
1. Открыть папку `C:\xampp\htdocs`.
2. Скопировать туда папку **os** (со всем содержимым: `index.html`, `api`, `sql`).
   Должно получиться `C:\xampp\htdocs\os\...`

Проверка: в браузере `http://localhost/os/` — платформа открывается.

---

## ШАГ 2. Удалить старую базу (чтобы не мешали прошлые ошибки)
1. Открыть `http://localhost/phpmyadmin`
2. Слева щёлкнуть базу **caseos** (если её нет — пропустите этот шаг).
3. Вверху вкладка **Operations** (Операции) → внизу
   **Remove database (DROP)** → подтвердить.
   (Если боитесь — можно не удалять; файл install_all.sql безопасен и для существующей базы.)

---

## ШАГ 3. Импорт ОДНОГО файла (создаёт базу + таблицы + роли)
1. В phpMyAdmin вверху вкладка **Import** (Импорт).
   ВАЖНО: базу слева заранее выбирать НЕ нужно — файл сам создаёт `caseos`.
2. **Choose File** → выбрать `os/sql/install_all.sql`
   (на компьютере путь `C:\xampp\htdocs\os\sql\install_all.sql`).
3. Нажать **Go** (Вперёд).
4. Внизу должно появиться зелёное «успешно» и таблица с числом **7**
   (это количество ролей). Это значит — всё встало.

Проверка: слева раскрыть `caseos` → должно быть ~18 таблиц
(roles, app_users, objects, units, … kp_counters).

---

## ШАГ 4. Настроить подключение (без ручного ввода)
1. Открыть папку `C:\xampp\htdocs\os\api`.
2. Найти файл **`config.local-xampp.php`**.
3. **Переименовать** его в **`config.php`** (правый клик → Переименовать).
   Внутри уже всё прописано для XAMPP — менять ничего не надо.

---

## ШАГ 5. Создать администратора (себя)
1. В браузере открыть `http://localhost/os/api/setup.php`
2. Ввести **email**, **пароль** (минимум 6 символов), **имя** → создать.
3. Должно написать «успешно».
4. Удалить файл `os/api/setup.php` (правый клик → Удалить) — это закрывает вход чужим.

---

## ШАГ 6. Проверка, что бэкенд живой
Открыть `http://localhost/os/api/auth.php`
— должно показать `{"auth":false}` (это нормально, значит API работает).

---

## ГОТОВО
- Платформа: `http://localhost/os/`
- База с таблицами и ролями стоит, вход создан.

## Как теперь выглядит вход (P2 — подключение к базе сделано)
Когда вы открываете `http://localhost/os/`, платформа сама находит базу и
показывает поле **Email** и **Пароль** — войдите теми, что задали в ШАГЕ 5.
- Данные теперь хранятся в **базе** (общие для всех сотрудников и устройств),
  а не в одном браузере. Любая правка автоматически сохраняется в базу.
- Перезагрузка страницы (F5) и вход с другого компьютера показывают
  те же самые данные.
- Если базы/API нет (например, открыли файл напрямую, без сервера) — включается
  старый демо‑режим с выбором роли из списка. Это нормально.

Проверьте сценарий: войдите → измените что‑нибудь (например, тему ☀️/🌙 или
помещение в реестре) → нажмите F5. Изменение должно остаться.

---

## Если опять ошибка — что именно прислать
Сфотографируйте/скопируйте КРАСНЫЙ текст ошибки целиком и напишите,
на каком ШАГЕ (0–6) она появилась. По номеру шага сразу пойму причину.

Частое:
- **#1050 «table already exists»** — не страшно, таблицы уже есть, можно идти дальше.
- **Apache не стартует** — порт 80 занят (Skype): в XAMPP сменить порт на 8080,
  тогда адрес станет `http://localhost:8080/os/`.
- **Белый экран на /os/api/** — проверьте, что переименовали config в `config.php`.
