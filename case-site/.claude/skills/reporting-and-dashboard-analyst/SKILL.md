## Purpose

Own the presentation and assembly layer of numbers in the Leasing & Sales Platform (LSP, `os/leasing/`, D1):

- the internal home dashboard ("What needs attention today?", 00_MASTER_PROMPT.md §33);
- the project dashboard (§63 screen 4) and the client dashboard KPI set (§35);
- the report generator (§37) and the "changes since previous report" mechanism (§2, §52);
- code-generated inline SVG charts (D14) and the print stylesheet (§37, §62).

Every number is computed from `appState.units` and `appState.deals` through `js/services.js` at render time
(§34: "Do not hard-code KPI values"), follows the anti-double-counting rules of D6, and is labeled as
inventory (unit-centric) or pipeline (deal-centric).

## Responsibilities

### Dashboard KPI cards (§33)

- Cards: active projects, total leasing GLA, total sales GLA, leased GLA, vacant GLA, GLA in negotiation,
  signed deals, sales pipeline value, overdue follow-ups, deals without next action, stale deals,
  missing documents, client comments awaiting response.
- Each card shows: value, denominator when a percentage is shown, an "inventory" or "pipeline" tag,
  and "n/a" (never 0) when inputs are missing (D6).
- "Today's work" and "Pipeline snapshot" blocks (§33) come from task, activity and deal queries in services.
- The "Data hygiene" block only renders results of the completeness/stale services owned by
  `data-quality-and-provenance`.

### Report generator (§37)

- `js/views/reports.js` renders; `js/services.js` builds section data (pure functions).
- Client report sections: executive summary, leasing and sales progress, leased/vacant/negotiating area,
  changes since previous report, floor/unit status, merchandise mix, client-approved key deals,
  decisions required, next steps, last updated timestamp.
- Internal report sections: Leasing (GLA by status, pipeline by stage and by manager, conversion, stage
  aging, signed deals, pending/received commissions, lost reasons, brands by category), Sales (available
  units/value, pipeline value, offers, negotiations, contracts, payments, commission status), Activity
  (overdue follow-ups, activities by manager, deals without next action, stale deals), Data quality
  (units without area/category, brands without contacts, duplicate contacts, outdated commercial terms).
- A generated report is saved to `appState.reports` as `RPT-nnn` with
  `{projectId, audience: 'client'|'internal', generatedAt, generatedBy, appVersion, kpiSnapshot, sections, demoRecord}`.
  Precedent: CASE OS `os/v4450-owner-report.js` builds one snapshot that powers text, table and plan
  views, and saved owner reports are stored client-safe.

### Changes since last report (§2, §37, §52 `getProjectChanges`)

- Baseline = the last `RPT-` record of the same project and audience.
- Content = KPI deltas versus `kpiSnapshot` + records dated after `previousReport.generatedAt`:
  `statusHistory` (SH-) entries, deal stage changes, signed deals, new client comments, document registrations.
- No previous report -> explicit message and a configurable fallback window (Settings, default 7 days).

### Charts and print

- Charts: inline SVG generated by code (bar, stacked bar, donut), no Chart.js (D14), readable in light and
  dark themes, with a text table beside every chart in print.
- Print: `@media print` rules in `css/lsp.css` for the print root in `index.html` (D2); hide navigation,
  drawer and toasts; A4 `@page`; header with project name, audience label, generated timestamp and
  `LSP_VERSION`; `break-inside: avoid` on KPI cards and tables; no horizontal overflow; a "DEMO DATA"
  line when the dataset is demo (D4).

## Constraints

- D6 is binding: inventory buckets partition unit-derived project GLA (Leased | Sold | Under negotiation |
  Available | Unavailable/Other); each unit's GLA appears in exactly one bucket; pipeline area is deal-based
  and the UI says "deal-based; units with several prospects appear more than once"; weighted pipeline
  value = sum of (annualised rent or agreed price) x stage probability; project `areas.glaM2` is shown as
  "declared GLA" and never silently substituted for the unit sum.
- D5: a unit's pipeline stage is derived from its open deals by services; reports never read a stage from
  `unit.commercialStatus`.
- D7: client dashboard and client report are built from `clientView(projectId)` output only; commissions,
  internal notes, proposed/negotiated terms, internal contacts and staff performance never reach client
  renderers (§35, §37, §38).
- §36: client-facing statuses use the configurable `clientStatus` mapping from `js/config.js`.
- Missing values are never zero (§65, §69); every percentage shows its denominator; "n units without area"
  is reported as a note.
- Colors, labels, thresholds and report visibility come from `DEFAULT_CONFIG` / Settings (§44).
- Charts and the print root run under the CASE OS CSP (`script-src 'self' 'unsafe-inline'
  https://cdn.jsdelivr.net`) and from `file://`: no external chart or PDF libraries, no `fetch()`.
- Do not modify CASE OS files (`os/index.html`, `os/core.js`, `os/sw.js`, `os/v*.js`, `os/api/*`, `os/sql/*`).
  Do not port the CASE OS PPTX export (external library) into LSP v0.1.
- No production claims: reports are prototype outputs from local data; say so in any README text you touch.
- Use the brief and 03_DATA_MODEL.md vocabulary (`glaM2`, `dealArea`, `deal.areaOverrideM2`, `countsAs`,
  `RPT-`, `SH-`, `AUD-`); do not invent parallel KPI names.

## Validation checklist

- [ ] Every KPI card maps to a named function in `js/services.js` and to a row in
      07_CALCULATIONS_AND_KPI_RULES.md; no literal numbers in views.
- [ ] Sum of inventory buckets equals unit-derived project GLA for Demo City Mall and Demo Business Park;
      the check exists as a Node test against `services.js`.
- [ ] The demo unit with 3 prospects is counted once in inventory and 3 times in deal-based pipeline area;
      the pipeline card carries the "deal-based" note.
- [ ] The multi-unit demo deal shows `dealArea` = sum of unique linked unit GLA (or `areaOverrideM2`).
- [ ] Removing the area of one demo unit turns affected KPIs into "n/a" or a "1 unit without area" note.
- [ ] Client report rendered for a `client` session contains no commission, internal note, proposed rent
      or internal contact string (string search in the QA script).
- [ ] "Changes since last report": no previous report -> message + fallback window; with a previous
      report -> deltas and record list consistent with `statusHistory`.
- [ ] Generated report persisted as `RPT-nnn` with `kpiSnapshot` and an `AUD-nnn` entry; survives refresh.
- [ ] Print preview at A4: no clipped tables, no navigation/drawer, header with timestamp and
      `LSP_VERSION`; headless Chromium "Save as PDF" produces all pages (§65 Reports).
- [ ] Dashboard renders without JS errors at 1920x1080, 1366x768 and 390x844; cards wrap, charts scale.
- [ ] All labels go through `t(key)`; EN and RU keys exist.
- [ ] Relevant `LSP-QA-nnn` ids from 10_QA_PLAN.md are named in the change note for `testing-and-qa`.

## Prohibited behavior

- Hard-coding KPI values, percentages or demo totals in views or reports.
- Reading a deal stage from `unit.commercialStatus`, or storing a derived KPI on any record.
- Summing unit GLA across deals for inventory metrics; presenting deal-based area as vacancy/occupancy.
- Treating missing area, rent, price or probability as zero; hiding denominators.
- Building the client dashboard or client report from `appState` directly instead of `clientView(projectId)`.
- Adding Chart.js or any external charting/PDF library.
- Printing through a popup window (`window.open` + `document.write`, the CASE OS pattern) when the
  in-page print root works; popups fail under `file://` and popup blockers.
- Changing stage probabilities, commission rules, stale thresholds or `countsAs` mappings; those belong to
  the owning skills listed under Hand-offs.
- Editing CASE OS files or `os/v4450-owner-report.js`; claiming LSP reports replace the CASE OS owner
  report in production.
- Writing model identifiers or session links into repository files.

## Examples

1. "The project dashboard shows Leased 62% but the units table says 58%."
   Expected: reproduce with the demo dataset in Node against `services.js`; determine whether the
   denominator differs (declared `glaM2` vs unit-derived GLA) or a Reserved/Fit-out unit is bucketed
   differently from `countsAs`; fix the single service function; add a Node assertion; report
   FACT / ASSUMPTION / RECOMMENDATION with both denominators shown side by side.
2. "Add 'changes since last report' to the client report."
   Expected: implement `getProjectChanges(projectId, sinceISO)` in services (statusHistory, deal stage
   changes, new client-visible documents, resolved comments), pass the result through `clientView`,
   baseline = last `RPT-` record with `audience:'client'`; render a dated list plus KPI deltas; add the
   fallback message; hand Flow 11 steps to `testing-and-qa` for `docs/qa/tools/lsp_reports.js`.
3. "Printing the internal leasing report cuts the pipeline-by-stage table."
   Expected: adjust `@media print` rules in `css/lsp.css` (table width 100%, `break-inside: avoid` per
   row group, landscape `@page` only for that report); verify in headless Chromium PDF output at A4;
   confirm the screen layout is unchanged at 1366x768.
