# CASE OS — установка на хостинг: пошагово (DirectAdmin)

Ваша схема:
- **платформа** → `https://caseadvisory.com/os/` (на `.uz` стоит редирект на `.com`,
  поэтому размещаем сразу на `.com`);
- **почта** → на `.uz` (там все ваши ящики): коды входа отправляются с
  `no-reply@caseadvisory.uz`.

Что понадобится: вход в DirectAdmin (`caseadvisory.uz:2222`, логин `wwwcasea`),
архив **case-os-v2.30.zip**, 30–40 минут. PHP 7.4 хостинга подходит (проверено).

---

## Шаг 1. Файлы — в public_html домена .com

Если папка `os` уже загружена на `.uz` (как сейчас):
1. **Система и файлы → Менеджер файлов** → откройте
   `domains/caseadvisory.uz/public_html`.
2. Галочка на папке **os** → кнопка **«Переместить»**.
3. Место назначения: `/domains/caseadvisory.com/public_html` → подтвердить.

Если загружаете заново: Менеджер файлов → `domains/caseadvisory.com/public_html`
→ **Загрузить** архив → выделить → **Extract**. Архив после распаковки удалить.

Проверка: в `domains/caseadvisory.com/public_html/os` есть `index.html`,
`api/`, `sql/`.

## Шаг 2. Проверить HTTPS

Откройте `https://caseadvisory.com/os/` — должен открыться экран входа CASE OS
с замочком в адресной строке. Если замочка нет: **Управление аккаунтом →
SSL-сертификаты** → включить бесплатный Let's Encrypt для caseadvisory.com.

## Шаг 3. Создать базу данных

**Управление аккаунтом → Базы данных → Create new Database**:
1. Имя базы: `os` → получится **`wwwcasea_os`**.
2. Пользователь: `os` → получится **`wwwcasea_os`**.
3. Пароль: сгенерировать и **сохранить**.

Запишите три значения: имя базы, пользователь, пароль. База общая для всего
аккаунта — от домена не зависит.

## Шаг 4. Импортировать таблицы

**Инструменты → phpMyAdmin** (вход — логин/пароль базы из шага 3):
1. Слева выбрать базу **wwwcasea_os**.
2. Вкладка **Импорт** → файлы из архива на вашем компьютере (папка `os/sql/`):
   - сначала `schema_mysql.sql` → **Go / Вперёд**;
   - затем `seed_roles.sql` → **Go**.

⚠️ `install_all.sql` не использовать — он только для локального XAMPP.

**Вариант Б — перенести данные с локального XAMPP**: на компьютере
`localhost/phpmyadmin` → база `caseos` → **Экспорт** («Быстрый») → полученный
файл импортировать в **wwwcasea_os** (вместо пунктов выше). Тогда шаг 7
пропускаете; проверьте, что у пользователей настоящие email.

## Шаг 5. Почтовый ящик для кодов входа (на .uz)

**Управление E-mail → E-Mail Аккаунты** → домен **caseadvisory.uz** →
**Create Account**: имя `no-reply` → получится `no-reply@caseadvisory.uz`,
пароль придумать и **сохранить**. (Можно использовать и существующий ящик —
тогда возьмите его адрес и пароль.)

## Шаг 6. Заполнить config.php

Менеджер файлов → `domains/caseadvisory.com/public_html/os/api/`:
1. Скопировать `config.sample.php` → имя копии `config.php`.
2. Открыть `config.php` → **Редактировать** → привести к виду:

```php
<?php
return [
  'driver' => 'mysql',
  'host'   => 'localhost',
  'name'   => 'wwwcasea_os',
  'user'   => 'wwwcasea_os',
  'pass'   => 'ПАРОЛЬ_БАЗЫ_ИЗ_ШАГА_3',
  'charset'=> 'utf8mb4',
  'sqlite_path' => __DIR__ . '/caseos.sqlite',
  'backup_token' => 'ПРИДУМАЙТЕ_ДЛИННУЮ_СЛУЧАЙНУЮ_СТРОКУ',
  'mail_from' => 'no-reply@caseadvisory.uz',
  'smtp' => [
    'host'   => 'mail.caseadvisory.uz',
    'port'   => 465,
    'secure' => 'ssl',
    'user'   => 'no-reply@caseadvisory.uz',
    'pass'   => 'ПАРОЛЬ_ЯЩИКА_ИЗ_ШАГА_5',
  ],
];
```

⚠️ Строки `'code_login' => false` быть **не должно** — она только для
локального XAMPP.

## Шаг 7. Создать первого администратора

1. Открыть `https://caseadvisory.com/os/api/setup.php`.
2. Ввести **ваш настоящий email** (на него будут приходить коды входа),
   пароль, имя → «Создать администратора».
3. **Обязательно удалить** файл `setup.php`: Менеджер файлов →
   `.../os/api/setup.php` → Удалить.

## Шаг 8. Проверить вход

1. `https://caseadvisory.com/os/`
2. Email из шага 7 → **«Получить код»**.
3. Код из письма (проверьте «Спам») → **«Войти»**.

## Шаг 9. Добавить сотрудников

Раздел **«Пользователи»** (виден только админу) → добавлять каждого с его
**настоящим рабочим email** (ящики на `.uz` подходят) — код входа приходит
на него.

## Шаг 10 (желательно). Автобэкап раз в день

**Доп. возможности → Cron задания → Create Cron Job**:
минута `0`, час `3`, остальное `*`; команда (подставьте свой `backup_token`
из шага 6):

```
curl -s "https://caseadvisory.com/os/api/backup.php?token=ВАШ_BACKUP_TOKEN" >/dev/null
```

Копии базы: `os/sql/backups/`, хранятся 30 дней. Вручную — кнопкой в платформе.

## Отдельно: сломанный редирект .uz → .com

Сейчас редирект приклеивает адрес без слэша:
`caseadvisory.uz/os/` → `caseadvisory.comos/` (несуществующий домен).
Это ломает **все** внутренние ссылки на `.uz`. Платформе это не мешает
(она на `.com`), но починить стоит: откройте
`domains/caseadvisory.uz/public_html/.htaccess` (Редактировать) и пришлите
скриншот содержимого — там, скорее всего, в правиле не хватает `/` перед `$1`,
например должно быть:

```
RewriteRule ^(.*)$ https://caseadvisory.com/$1 [R=301,L]
```

## Если что-то пошло не так

| Симптом | Причина и решение |
|---|---|
| «Неизвестное действие» при входе | На сервер попала не вся папка `os/api` — перезалейте её целиком из архива. |
| «Хостинг не отправил письмо» | Проверьте блок `smtp`: host `mail.caseadvisory.uz`, порт 465/ssl, точный пароль ящика. Аварийно: добавьте `'allow_password_login' => true,` — временно включится вход по паролю; после починки почты уберите. |
| Письмо не приходит | Папка «Спам»; новый код — не чаще раза в минуту. |
| «Этот email не зарегистрирован» | В «Пользователи» проверьте написание email сотрудника. |
| Ошибка базы при открытии | Сверьте `name`/`user`/`pass` в config.php с шагом 3. |
| Обновление не видно | Ctrl+F5. |

## Обновления платформы в будущем

Из нового архива заменить: `os/index.html`, `os/sw.js`, `os/quiz-data.js`
и папку `os/api` (ваш `config.php` не трогать — в архивы он не входит).
После замены — Ctrl+F5.

Локальный XAMPP можно оставить как тренировочный: с `'code_login' => false`
он работает по паролю независимо от хостинга.
