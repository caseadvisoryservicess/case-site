# CASE OS v4.59.0

Дизайн и эргономика. Отдельно - гео-студия: это тот экран, который показывают клиенту
и по которому продают подписку, а он единственный в системе жил на чужой палитре.

## Что было видно на экране и чего там быть не должно

Прогон в настоящем браузере по всем разделам на пяти разрешениях показал вещи, которые
статические проверки не ловят, потому что синтаксис у них правильный:

- на главном экране в показателе «Ср. сервис-чардж» стояло **NaN%**. Складывали поле `sc`
  по всем проектам, а у проекта без сервис-чарджа поля просто нет - `undefined` в сумме
  давал NaN. Ноль тут тоже неправда: «нет данных» и «ноль процентов» - разные утверждения.
  Теперь считаем только по проектам, где значение есть, а при их отсутствии пишем `-`.
  То же исправлено у средней заполняемости и средней ставки;
- в реестре под каждой категорией стояло слово **undefined** - подкатегорию выводили без
  проверки. Строку показываем только когда подкатегория заполнена;
- в шапке экрана висел **пустой серый обрубок** - это тарифный бейдж проекта, который
  рисовался даже с пустым значением;
- **две «текущие» вкладки одновременно.** В реестре подряд идут два ряда вкладок: где я
  нахожусь (таблица / планировка / канбан) и раздел внутри вида (план-бюджет / изменения /
  отказы). Оба рисовали залитую чёрную таблетку, и понять своё место было нельзя. Теперь
  первый уровень остался таблеткой, второй стал подчёркиванием - одно активное состояние
  на уровень;
- **кнопка «наверх» лежала на бейдже теста**: обе фиксированы у правого края с разницей в
  6px при высоте 44px. Разнесли по одной колонке. Регресс-тест теперь проверяет само
  требование (плавающие кнопки не пересекаются), а не запомненное число 86px - старый тест
  закреплял именно ту раскладку, в которой они и перекрывались;
- заголовок группы меню обрезался посреди слова («АРЕНДА И ПРОДАЖИ (LEASING & SA») -
  теперь ужимается многоточием.

## Один неизвестный статус больше не гасит экран планировок

`stT` возвращал `undefined` для статуса, которого нет в словаре (пришёл из импорта CSV или
остался от старой записи), и `planSVG` падал на `planLabel(u).toUpperCase()` - весь раздел
«Планировки» оставался пустым, без единого слова о причине. Теперь отдаём сам код статуса,
как это давно делает функция для статусов продажи: экран строится, а странное значение
видно глазами и его можно поправить в реестре.

## Гео-студия: продуктовый вид

Студия писалась как внутренний инструмент и осталась на своей палитре - холодный
сине-серый против тёплой бумаги остальной системы. В одном продукте это читалось как две
разные программы. Переведена на палитру CASE: тёплая бумага, оксблад, Montserrat, единая
шкала подписей. Ничего не переставляли - поменяли материал, из которого сделан экран.

- **командный блок закреплён.** Проект, его район и координаты, кнопки анализа и выгрузки
  больше не уезжают вверх, когда листаешь список слоёв;
- **сведения о проекте стали данными, а не абзацем.** Было четыре строки подряд, где имя
  проекта дублировало выпадающий список прямо над ним, а «Район: -» не сообщало ничего.
  Стало: слева подпись, справа значение, отсутствие данных названо словами
  («не определён», «не заданы»), а «требуется проверка» - отдельный статусный значок;
- **главное действие читается как главное.** «Выгрузить PDF · Excel · PPTX» умещается в
  одну строку и залито фирменным красным; «Настройки» рядом - вторичная кнопка;
- **переключатель подложки перестал быть пустым белым квадратом.** Leaflet берёт для него
  иконку картинкой `layers.png`, которой в сборке нет, - контрол выглядел как элемент,
  который не догрузился. Иконка нарисована средствами CSS, ничего внешнего не подключаем;
- **на телефоне кнопка слоёв больше не лежит на кнопке зума** - переехала вниз-влево и
  выросла до 44px;
- вкладки прокручиваются с подсказкой, что справа есть ещё; зум, атрибуция и легенда
  оформлены в фирменном виде;
- убран внутренний жаргон в подписях: «Анализ локации (как в гео-платформах)» →
  «Анализ локации», «Зона охвата (catchment)» → «Зона охвата», названия источников
  (`OSM`, `clinics.uz`) ушли из подписи слоя в подсказку. Трёхстрочное пояснение под
  кнопкой выгрузки сжато до одной строки.

## Единая визуальная система

До этого каждый модуль приносил свою форму кнопки и свою высоту поля: на одном экране
реестра - семнадцать управляющих элементов четырёх разных форм и высот 30/34/36/38.
Согласовано в одном слое (`v4450-ux-system.js`), поверх уже существующей палитры CASE:

- одна высота у всего, на что нажимают;
- одна шкала показателя: подпись тише, число громче, единица не спорит с числом;
- одна ступень заголовка карточки;
- строка таблицы, открывающая карточку, показывает это курсором и подсветкой;
- шрифты мельче 9px подняты (37 мест), правило внутри `@media print` не тронуто;
- на телефоне ряды «заголовок + кнопки» переносятся, а не сжимаются в столбик из двух букв.

## Проверено

- браузерный прогон: 5 разрешений (1920 / 1366 / 1024 / 768 / 390) × 8 разделов -
  20 проверок, все зелёные: ошибок сценария нет, боковой прокрутки нет, за правый край
  ничего не выходит, строки таблиц не подменены кнопками, кнопок без доступного имени 0,
  кликабельных блоков без клавиатуры 0, текстов мельче 9px 0;
- 25 регрессионных наборов (реестр, роли, права, живая синхронизация, закрепление
  столбцов, ширины, конфликты CSS, обход всех разделов) - без отказов;
- гео: легенда, F&B, образование, слои POI, выгрузка - без отказов;
- выгруженные `.xlsx` и `.pptx` открыты настоящими библиотеками (openpyxl, python-pptx),
  45 проверок пройдено, длинных и средних тире в видимом тексте - ноль;
- инварианты релиза: версия, кэш, комментарий service worker, DEPLOY.md, манифест сумм,
  cache-buster каждого модуля, наличие каждого подключённого скрипта в офлайн-кэше.

## Что стоит решить по гео-студии отдельно

Разбор семи вкладок студии по тому, насколько они привязаны к проекту и обновляемы:

| Вкладка | Привязана к проекту | Данные обновляются |
|---|---|---|
| Карта | да - точка, радиусы, зона охвата | слои тянутся с сервера и из OSM |
| Профиль проекта | да - свой набор полей под тип объекта, файлы | да, прямо в карточке |
| Генплан / нормы | да - FAR, застройка, конверт GFA, файлы-основания | да, ручная проверка |
| Аналитика | почти нет - из всего экрана к проекту относится один блок | считается из общих данных |
| Управление данными | нет, общая база БЦ / медицины / POI | да, импорт и правка |
| Объекты на карте | нет, портфель CASE | да |
| Сравнение стран | нет | **нет - таблица зашита в код** |

«Сравнение стран» - единственное место, где цифры (ставки и вакантность по столицам
региона) лежат константой в исходнике: обновить их из интерфейса нельзя, и они стареют
молча. Для продукта по подписке это либо переносится в редактируемый набор данных с
источником и датой, либо убирается из клиентской версии. «Аналитика» дублирует общую
статистику города на каждом проекте - её место либо в «Карте» отдельной панелью, либо
она должна считаться по выбранному проекту. Механизм скрытия вкладок по роли уже есть
(внешним пользователям не показывают «Объекты на карте») - его же можно применить, чтобы
клиент по подписке видел три вкладки вместо семи. Ни того, ни другого в этом релизе не
делаю: это меняет состав продукта, а не его вид.
