# CASE OS — простое руководство (для не‑программиста)

Пошагово: от нуля до запуска и до установки обновлений. Технических знаний
не требуется — просто повторяйте по пунктам.

---

## 0. Как это устроено (одним абзацем)
Платформа состоит из двух частей:
1. **Файлы программы** — лежат на хостинге в папке `os` (это «сама программа»).
2. **База данных** — отдельное хранилище, где живут все ваши данные (помещения,
   бренды, документы, пользователи).

Главное правило: **обновление файлов программы не трогает базу данных**.
Поэтому новые версии ставятся поверх, а данные остаются на месте.

> Статус: готово полностью — база, вход по email/паролю И подключение экрана
> платформы к базе (шаг «P2») сделаны и протестированы. Все данные хранятся
> в базе и общие для всех сотрудников; вход — по рабочему email и паролю.

---

## 1. Что понадобится
- Хостинг (у вас webspace.uz) и домен **caseadvisory.uz**.
- Доступ в **cPanel** (панель управления хостингом: адрес, логин, пароль —
  их даёт хостинг‑провайдер).
- Файлы платформы (я присылаю архивом `os-deploy.zip` и отдельными файлами).

---

## 2. Первая установка (делается один раз)

### Шаг 1. Войти в cPanel
Откройте адрес панели от webspace.uz, введите логин и пароль. Откроется
страница с иконками (Files, Databases, и т.д.).

### Шаг 2. Загрузить файлы платформы
1. cPanel → раздел **Files** → **File Manager**.
2. Откройте папку **public_html** (это «корень сайта»).
3. Кнопка **Upload** вверху → выберите архив `os-deploy.zip` → дождитесь 100%.
4. Вернитесь в File Manager, нажмите правой кнопкой на `os-deploy.zip` →
   **Extract** (распаковать). Появится папка **os** со всеми файлами.
5. Архив `os-deploy.zip` можно удалить.

### Шаг 3. Создать базу данных
1. cPanel → раздел **Databases** → **MySQL Database Wizard** (мастер).
2. **Step 1:** придумайте имя базы, напр. `os` → **Next Step**.
   (Полное имя получится вида `caseadv_os` — запишите его.)
3. **Step 2:** придумайте пользователя базы и **пароль** (нажмите Password
   Generator, скопируйте и сохраните пароль!) → **Create User**.
4. **Step 3:** отметьте **ALL PRIVILEGES** (все права) → **Next Step**.
5. Запишите три значения: **имя базы**, **имя пользователя**, **пароль**.

### Шаг 4. Загрузить структуру базы
1. cPanel → **Databases** → **phpMyAdmin**.
2. Слева выберите вашу базу (имя из шага 3).
3. Вкладка **Import** (Импорт) вверху → **Choose File** → выберите
   `os/sql/schema_mysql.sql` (он уже на хостинге, но загружать в Import нужно
   с компьютера — поэтому держите эти SQL‑файлы и у себя) → **Go**.
4. Повторите Import ещё раз для файла `os/sql/seed_roles.sql` → **Go**.
   (Это создаст таблицы и 7 ролей. Должно написать «успешно».)

### Шаг 5. Вписать данные базы в настройку
1. File Manager → откройте папку `os` → `api`.
2. Найдите файл **config.sample.php** → правый клик → **Copy** → укажите имя
   `config.php` (то есть сделайте копию с именем config.php в той же папке).
3. Правый клик по **config.php** → **Edit** (редактировать).
4. Впишите ваши значения из шага 3:
   - `'name' => 'ИМЯ_БАЗЫ'` → ваше имя базы;
   - `'user' => 'ПОЛЬЗОВАТЕЛЬ_БАЗЫ'` → ваш пользователь;
   - `'pass' => 'ПАРОЛЬ_БАЗЫ'` → ваш пароль.
   `'driver'` оставьте `'mysql'`, `'host'` оставьте `'localhost'`.
5. **Save Changes** (сохранить).

### Шаг 6. Включить HTTPS (защищённое соединение)
1. cPanel → раздел **Security** → **SSL/TLS Status**.
2. Найдите домен caseadvisory.uz → нажмите **Run AutoSSL** (выпустит
   бесплатный сертификат). Если опции нет — попросите поддержку webspace.uz
   включить бесплатный Let’s Encrypt SSL.

### Шаг 7. Создать первого администратора (вас)
1. В браузере откройте: `https://caseadvisory.uz/os/api/setup.php`
2. Введите свой **email**, **пароль** (минимум 6 символов) и имя → нажмите
   «Создать администратора».
3. Появится сообщение об успехе.
4. **ВАЖНО:** вернитесь в File Manager → `os/api/` → удалите файл
   **setup.php** (правый клик → Delete). Это закрывает вход для посторонних.

### Шаг 8. Открыть платформу
Откройте `https://caseadvisory.uz/os/` — это рабочий адрес. Дайте эту ссылку
сотрудникам.

Готово. Установка завершена.

## 3. Добавление сотрудников
Пользователей заводит администратор (вы). Каждому — email, пароль и роль
(например, «Агент аренды»). Роль определяет, что человек видит и может менять
(финансы, правки, «только свои сделки» и т.д.). Управление пользователями и
правами — в разделе **«Пользователи»** внутри платформы.

---

## 4. Резервная копия (бэкап) — делайте перед каждым обновлением
1. cPanel → **phpMyAdmin** → выберите вашу базу слева.
2. Вкладка **Export** (Экспорт) → метод **Quick** → формат **SQL** → **Go**.
3. Сохранится файл — это полная копия всех данных на текущий момент.
Храните такие копии; из них можно восстановиться, если что‑то пойдёт не так.

(Дополнительно: cPanel → **Backup** делает копию всего аккаунта — можно
настроить автоматически.)

---

## 5. Установка обновлений

Я присылаю новую версию. Возможны два случая.

### Случай A — обычное обновление (чаще всего)
Это когда меняется только программа (интерфейс, документы, логика).
1. Сделайте **бэкап базы** (раздел 4) — на всякий случай.
2. File Manager → папка `os` → **Upload** → загрузите новый `index.html`
   (и, если я указал, другие файлы) → подтвердите замену (**Overwrite**).
3. Готово. Данные не меняются.

> Файл `os/api/config.php` **никогда не заменяйте** — там доступ к вашей базе.
> Я в обновлениях его не присылаю.

Если после обновления у кого‑то «старая версия» — пусть обновят страницу
(Ctrl+F5) или один раз закроют/откроют вкладку.

### Случай B — обновление с изменением базы (реже)
Это когда в новой версии появляются новые поля/таблицы. Я предупрежу и пришлю
файл‑миграцию (например `2026_07_15_*.sql`).
1. Сделайте **бэкап базы** (обязательно).
2. File Manager → `os/sql/migrations/` → **Upload** присланный файл миграции.
3. Загрузите обновлённый `index.html` и другие файлы (как в случае A).
4. Войдите как администратор и откройте один раз:
   `https://caseadvisory.uz/os/api/migrate.php`
   Появится сообщение, что миграция применена (повторный запуск ничего не
   испортит — применяются только новые файлы).
5. Готово. Все старые данные на месте, добавилось только новое.

## 6. Золотые правила (чтобы не потерять данные)
- Перед любым обновлением — **бэкап базы**.
- **Не заменяйте** `os/api/config.php`.
- **Не запускайте повторно** `schema_mysql.sql` на рабочей базе (он только для
  самой первой установки).
- В phpMyAdmin не нажимайте **Drop** (удалить) и **Truncate** (очистить) на
  таблицах — это стирает данные.
- Обновляйте файлы только теми, что я прислал для этой версии.

---

## 7. Если что‑то пошло не так
- **Платформа не открывается / белый экран:** проверьте, что в `config.php`
  правильно вписаны имя базы, пользователь и пароль (шаг 5).
- **«Неверный логин или пароль»:** сбросьте пароль пользователя (это умеет
  администратор в разделе «Пользователи»), либо проверьте email.
- **После обновления что‑то сломалось:** восстановите базу из бэкапа
  (phpMyAdmin → ваша база → Import → выберите сохранённый файл бэкапа → Go) и
  напишите мне — поправлю.
- **Нужна помощь хостинга** (SSL, доступы): пишите в поддержку webspace.uz.

---

## Мини‑словарь
- **cPanel** — панель управления хостингом (где вы нажимаете кнопки).
- **File Manager** — менеджер файлов, как «Проводник» на хостинге.
- **public_html** — корневая папка сайта.
- **База данных (MySQL)** — хранилище ваших данных.
- **phpMyAdmin** — программа для работы с базой (импорт, экспорт/бэкап).
- **Бэкап** — резервная копия данных.
- **Миграция** — небольшой файл, который аккуратно добавляет новое в базу,
  ничего не удаляя.
- **HTTPS / SSL** — защищённое (зелёный замочек) соединение, обязательно.
