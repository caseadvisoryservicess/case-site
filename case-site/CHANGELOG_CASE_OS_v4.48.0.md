# CASE OS v4.48.0 — шапка таблиц больше не может разъехаться (клон удалён)

Дата: 2026-07-25. Ответ на «всё равно всё сбивается при малейшем движении».

## Суть

Все «сбитые линии», «белые пятна» и «съехавшие столбцы» происходили из одного
архитектурного решения: прилипшая шапка была **копией** настоящей шапки,
которую отдельный код должен был успевать синхронизировать с таблицей при
каждом движении. Любая гонка, зум, рамка или старый файл — и копия расходилась
с телом.

В v4.48.0 копия удалена полностью. Прилипает **настоящий thead** самой таблицы
(нативный position:sticky): шапка и тело — один элемент, разойтись им
физически невозможно — ни линиям, ни закреплённым столбцам, ни при каком
движении, зуме или частичной заливке.

## Что изменилось технически

- обёртке главной таблицы задаётся высота по экрану — вся вертикальная
  прокрутка строк идёт внутри таблицы (стандарт для больших гридов), шапка
  всегда достижима;
- вертикально прилипает весь `thead` (обнаружен и учтён баг Chromium: sticky
  на отдельных `th` вертикально не работает при table-layout:fixed+colgroup —
  из-за него когда-то и появился клон); горизонтально закреплённые столбцы —
  sticky по left, как раньше;
- найден и удалён второй исторический виновник: резайзеры ставили каждому th
  инлайновый position:relative, который глушил родные sticky-правила шапки,
  лежавшие в коде с ранних версий;
- удалено ~80 строк кода синхронизации клона (слой, отпечатки, проброс событий
  резайзеров и кликов) — этому коду больше нечего рассинхронизировать;
  прокрутка колёсиком с передачей странице и авто-высота сохранены;
- резайзеры работают прямо в прилипшей шапке — это те же самые ручки той же
  самой таблицы.
