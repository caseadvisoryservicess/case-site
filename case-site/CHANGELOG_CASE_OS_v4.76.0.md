# CASE OS v4.76.0

Замечания владельца после v4.75.0 (десять пунктов по студии и модель доступа): пин без
колец, свой цвет у каждого кольца, полный экран карты, левая панель сворачивается, подложка в
панели инструментов, лишнее убрано (вкладка «Сравнение стран», кнопка «Точка на карте»,
строка-подсказка над студией), экран «Geo Platform: бизнес-центры» слит со студией, и новая
модель доступа: типы пользователей, настройки на каждого, журнал, корзина, подписка со сроком,
регистрация, демо-вход.

## Студия геоаналитики

- **Пин ставит только точку.** Кольца охвата больше не появляются сами: по умолчанию они
  выключены, пользователь включает нужные в «Зоне охвата» (память v2 хранит флажки и цвета).
- **Свой цвет у каждого кольца.** Рядом с каждым радиусом кнопка цвета; общий выбор цвета у
  толщины линий убран.
- **Полный экран карты.** Кнопка ⛶ в панели инструментов разворачивает область карты вместе с
  панелью инструментов, агентом и плашкой «На экране»; левая панель на это время скрыта, Esc
  возвращает. Внутри платформы у iframe студии включён `allowfullscreen`; без Fullscreen API
  работает запасной режим на весь видимый экран.
- **Левая панель сворачивается целиком.** Язычок у левого края карты, состояние помнится.
- **Подложка карты в панели инструментов.** Кнопка с именем текущей карты и списком (OSM,
  Google, 2GIS, Яндекс, Esri) стоит в нижней панели вместо кнопки «стиль»; правый верхний
  угол свободен.
- **Убрано:** вкладка «Сравнение стран», кнопка «📍 Точка на карте» в левой панели (точку ставят
  пин P и правый клик), строка-подсказка над студией в платформе.
- **Бизнес-центры внутри студии (`os/v4760-geo-bc.js`).** Секция «Бизнес-центры» в левой панели:
  поиск, фильтры по району, классу, источнику и проверке, «только с известной ставкой», «только с
  правками», счётчик «найдено N из M»; карта, счёт по кольцам и показатели показывают только
  отфильтрованные объекты; список с расстоянием до точки анализа, переходом на карту и в
  карточку; сравнение до четырёх БЦ таблицей с CSV (пустая ячейка значит «нет данных»);
  показатели выборки с честными знаменателями; слой «Тепловая карта ставок (известные значения)»
  в категории «Бизнес-центры» с легендой в плашке «На экране». Редактор записей с
  происхождением полей остаётся карточкой БЦ.
- **Экран «Geo Platform: бизнес-центры» убран** из меню и из платформы (`os/geo-platform.html`
  удалён): те же данные показывались двумя экранами и путали. Автономный файл
  `docs/standalone/CASE_Geo_Platform_MVP.html` остаётся отдельным продуктом для клиентов.

## Модель доступа

- **Типы входа:** администратор (флаг роли), сотрудник (внутренние роли), клиент (роль `CL`:
  только студия геоаналитики), демо (роль `DEMO`). Сервер: `user_type`, `expires_at`,
  `settings` в `app_users` (колонки дочиниваются сами при первом обращении, есть и миграция
  `os/sql/migrations/2026_09_17_v4760_access.sql`), `user_caps()` для интерфейса.
- **Настройки на пользователя** (страница «Доступ», карточка «Доступ, подписка и журнал»): тип,
  срок, выгрузка, правки, заметка. `users.php` `set_profile`. Клиент без правок не пишет
  геоданные (роль без edit), сотрудник по своей роли.
- **Журнал по пользователю:** кнопка «Журнал» открывает действия из `audit_log` (`users.php`
  `log`): входы, сохранения, изменения доступа, отказ по сроку.
- **Корзина геоданных:** строки, пропавшие из наборов при сохранении `geo_state.php`, попадают
  в таблицу `geo_trash` с автором и временем; администратор видит их в карточке «Корзина
  геоданных» и восстанавливает одной кнопкой (`restore_trash`); запись возвращается в свой
  набор, журнал отмечает восстановление.
- **Подписка:** по окончании срока (день включительно) вход отвечает 403 «Срок доступа истёк.
  Данные сохранены», текущий сеанс закрывается (`auth: false, expired: true`), учётная запись и
  данные остаются; за 5 дней и меньше пользователь видит предупреждение вверху платформы и в
  студии. Администратор продлевает срок в карточке доступа.
- **Регистрация:** ссылка на экране входа, форма (имя, компания, email, телефон, пароль). Заявка
  создаёт отключённого клиента; ответ одинаков для нового и занятого email. Вход по
  неподтверждённой заявке объясняет причину. Администратор видит карточку «Заявки на
  регистрацию» и открывает доступ с датой и правом выгрузки или отклоняет.
- **Демо-вход:** ссылка на экране входа, общий демо-пользователь. Ничего не сохраняет (сервер
  отвечает 403 на запись состояния и геоданных), студия показывает 40 бизнес-центров из базы,
  без выгрузки, правок и вкладки «Управление данными», с пояснением.
- Ключи `config.php`: `'allow_registration' => false` отключает регистрацию, `'demo_login' =>
  false` отключает демо, `'demo_email'` меняет адрес демо-пользователя.

## Ловушки

- Ядро собирает `S.user` заново из ответа сервера и не знает новых полей: тип, срок и права
  дописываются после `applyServerUser`, иначе студия не узнаёт о демо.
- `BC` в студии объявлен через `const`: снаружи (из тестов) он виден только через `eval` в её
  окне.
- После `session_destroy()` новый CSRF-токен не сохраняется, и следующий вход падает с «сессия
  устарела»: закрытый по сроку сеанс очищается через `session_regenerate_id(true)`.
- Клиентские пресеты ролей (`v3520-workspaces.js`) должны знать роли CL и DEMO, иначе меню
  клиента пустое даже при верном ответе сервера.
