# CASE OS v4.49.0 — ядро вынесено из index.html: страница легче в 18 раз

Дата: 2026-07-25.

## Что было не так

`index.html` весил **1004 КБ**, и 94% этого объёма — код платформы, лежавший прямо внутри
страницы. Разметки там всего 7 КБ. При этом номер версии в шапке меняется каждый релиз, а
значит браузер каждый раз считал файл новым и **скачивал весь мегабайт заново** — даже когда
менялся один модуль и ни строчки ядра.

Замер по девяти последним релизам показал главное: `index.html` менялся на 4–25 строк, и почти
всё это — номер версии и теги подключения. Сама логика ядра менялась только в трёх релизах из
девяти, и то на 4–8 строк. То есть мегабайт перекачивался практически впустую.

## Что сделано

Код ядра вынесен в отдельный файл `os/core.js`. Теперь:

- **`index.html` — 56 КБ** вместо 1004 КБ: разметка, стили и номер версии;
- **`core.js` — ядро**, подключается обычным тегом на том же месте, где раньше стоял код,
  поэтому порядок выполнения не изменился ни на шаг;
- номер версии платформы намеренно **оставлен в `index.html`**. Если бы он уехал в ядро, ядро
  менялось бы каждый релиз и весь смысл пропал бы. Ядро получает собственный номер, который
  поднимается только при реальной правке ядра.

Итог для сотрудника: при обновлении, не затрагивающем ядро, браузер докачивает **56 КБ вместо
1004 КБ**. По статистике последних релизов это две трети всех обновлений. Для работы с телефона
разница заметная.

Попутно: ядро включено в сверку версий файлов, так что при неполной заливке платформа скажет
об этом сама, и добавлено в список кэшируемых файлов.

## Проверка

Полный прогон, **245 проверок — всё зелёное**: полный QA 34/34, ядро снапшотов 19/19,
надёжность сохранений 14/14, закрепление и прилипание 13/13, синхронизация 12/12, гео-отчёт
10/10, визуальная стабильность 9/9, карточки 8/8, смоук слияния 8/8, гео-студия 14/14 и 8/8,
сценарии ролей 27/27, матрица доступов 54/54, настройки таблиц 3/3, live-edit 5/5.
Отдельно проверено: ядро запрашивается и отвечает 200, вход работает, все девять разделов
открываются, 0 JS-ошибок.

Тесты, читавшие код из `index.html`, теперь читают `index.html` плюс `core.js` — работают и
со старой, и с новой структурой.

Серверные PHP не менялись.

## Обновление — внимание, важно

Залить `CASE_OS_v4.49.0_os_only.zip` в `/os` **целиком, с перезаписью**. В архиве появился
**новый файл `os/core.js`** — без него платформа не запустится вообще (пустая страница).
Обычная распаковка архива поверх папки его добавит; главное — не заливать выборочно
отдельные файлы.

После заливки: Ctrl+Shift+R, в шапке должно быть **v4.49.0**, жёлтого предупреждения о старых
файлах быть не должно.
