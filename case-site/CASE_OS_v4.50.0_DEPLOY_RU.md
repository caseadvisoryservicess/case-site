# CASE OS v4.50.0 — установка

## Коротко

1. Скачайте `CASE_OS_v4.50.0_os_only.zip`.
2. В DirectAdmin → Менеджер файлов перейдите в `domains/caseadvisory.uz/public_html/`.
3. Загрузите архив и распакуйте с **перезаписью** папки `os`.
4. Откройте сайт и нажмите `Ctrl+Shift+R`.
5. В шапке должно быть **v4.50.0**, предупреждения о старых файлах нет.

Архив содержит только папку `os`. `config.php` в нём нет — доступ к базе не затрагивается.

## Что изменилось

Изменены три файла: `os/index.html`, `os/core.js`, `os/sw.js`.
Серверные PHP не менялись, миграций базы нет, откат — возврат прежней папки `os`.

Сохранение больше не отправляет на сервер разделы, закрытые для роли сотрудника.
Раньше браузер слал их пустыми при каждом сохранении, сервер записывал отказ в журнал
и откатывал значение: 400 таких записей за неделю, за которыми не было видно настоящих
проблем. Предупреждение «НЕ сохранено» теперь повторяется через 10 минут, а не показывается
один раз за сессию.

## Как убедиться, что помогло

Через день-два запустите в терминале:

```bash
cd ~/domains/caseadvisory.uz/public_html/os
php deep_check.php
```

В разделе 4 количество отказов должно резко упасть. Всё, что там останется, —
настоящие попытки записать закрытый раздел, и их уже стоит разбирать.

Скрипт `deep_check.php` после проверки удалите: `rm deep_check.php`.

## Если что-то пошло не так

- **В шапке старая версия** — браузер держит кэш: `Ctrl+Shift+R`, на телефоне закрыть
  и открыть вкладку заново.
- **Предупреждение о старых файлах** — залилась не вся папка `os`. Распакуйте архив
  ещё раз с перезаписью и проверьте, что на месте `core.js`.
- **Проверить полноту заливки** — залейте `server_check.php` в `os` и запустите
  `php server_check.php`: раздел 1 покажет версии всех модулей и контрольные суммы.
