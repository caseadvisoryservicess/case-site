# CASE OS v4.33.0 — Changelog

Дата релиза: 24 июля 2026 г.

## Главное: закрыт P0-1 внешнего аудита (версии планировок ↔ реальный чертёж)

До v4.33.0 «версия планировки» была меткой: генерация LCR всегда читала глобальный
`PLAN_CODES` (последний загруженный чертёж), а переключение версии меняло только подпись.

### Неизменяемые снапшоты версий

- У каждой версии планировки теперь есть **снапшот**: коды и площади помещений
  (`PLAN_CODES` проекта), блоки/этажи (`PLAN_STRUCT`), сами SVG-чертежи (по хешу,
  без дублирования), **контрольная сумма**, автор и дата фиксации.
- Снапшот **неизменяем**: после фиксации он глубоко замораживается (`Object.freeze`),
  повторная фиксация в ту же версию запрещена, при загрузке состояния с сервера
  снапшоты замораживаются заново. Новый чертёж — всегда новая версия.
- SVG хранятся в дедуп-хранилище `PLAN_SNAPSHOT_SVGS` (ключ — хеш содержимого):
  одинаковые чертежи в нескольких версиях не раздувают состояние; хранилище входит
  в серверный блоб и исключено из localStorage в backend-режиме (как и другие
  тяжёлые данные — правило P1-4).

### Генерация LCR — строго из снапшота

- Вкладка «Генерация LCR» получила **выбор версии-источника**; предпросмотр и
  применение считаются по снапшоту выбранной версии, а не по «тому, что сейчас на плане».
- Версия без снапшота (legacy или свежесозданная рабочая) получает снапшот
  автоматически при первой генерации; повторные генерации идут из него же.
- Advisory-передача (`Готово для аренды`) фиксирует снапшот в момент handover —
  аренда принимает именно тот чертёж, который ей передали.
- Если текущий чертёж во вкладке «Планировки» разошёлся со снапшотом выбранной
  версии — показывается предупреждение с контрольными суммами и кнопкой
  «＋ Версия из текущего чертежа».
- Созданные/обновлённые юниты получают `layoutVersionId` **и** `snapshotChecksum`;
  история юнита содержит номер версии и контрольную сумму (полная трассируемость).

### «Создать помещения из чертежа» и «Обновить площади» тоже трассируются

- Быстрые инструменты вкладки «Планировки» теперь работают через версию,
  чей снапшот соответствует текущему чертежу: при необходимости снапшот
  фиксируется в активную версию или создаётся новая авто-версия
  («Текущий чертёж (авто)») — с записью в аудит.

### Прочее

- Вкладка «Версии»: колонка «Снапшот чертежа» (🔒 контрольная сумма, число кодов,
  дата/автор; отметка «= текущий чертёж»), кнопки «📸 Зафиксировать» и
  «＋ Версия из текущего чертежа».
- «История»: событие «Снапшот версии … зафиксирован #…».
- Юниты: в колонке «Версия» показывается контрольная сумма снапшота-источника.
- Исправлено: `v4327-patch.js` перезаписывал номер версии платформы в шапке
  своим `PATCH_VERSION` (терялся префикс DEMO и актуальный номер).
- Исправлено: возможная коллизия id версий, создаваемых в одну миллисекунду.

## Технические изменения

- Версия платформы: `4.33.0`.
- Service Worker cache key: `case-os-v4330`.
- Подключён `v417-master-plan.js?v=4.33.0`.
- Новые поля состояния: `PLAN_SNAPSHOT_SVGS` (в `stateBlob`/`applyState`,
  в списке тяжёлых ключей `_HEAVY_LOCAL_KEYS`), `CASE_LAYOUT_VERSIONS[].snapshot`,
  `U[].snapshotChecksum`.
- SQL-миграция **не требуется** (снапшоты живут в общем блобе состояния `app_state`).

## Совместимость

Существующие версии планировок без снапшота продолжают работать: снапшот
зафиксируется при первой генерации LCR или вручную кнопкой «📸 Зафиксировать».
Данные LCR, брендов, сделок, ставок и прав пользователей не изменяются.
