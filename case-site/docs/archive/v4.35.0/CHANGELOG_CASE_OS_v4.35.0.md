# CASE OS v4.35.0 — Changelog

Дата релиза: 24 июля 2026 г.

## Главное: закрыт ВЕСЬ остаток внешнего аудита (P1-1, P1-2, P1-3, P1-5, P1-6, P2) + проход по ролям и безопасности

### P1-1 — коммерческая защита юнита стала project-scoped

- Сделка привязывается к юниту в первую очередь по точному `unitId` (его пишут
  авто-сделки и `unit_patch`), затем по коду помещения — но только в паре с объектом
  сделки. Одинаковый код помещения в другом проекте больше не защищает
  (и не разблокирует) чужой юнит.
- Сделка без `unitId` и без объекта защищает по коду консервативно (лучше лишний замок).

### P1-2 — массовый override защищённых площадей удалён

- Галки «менять и защищённые площади» больше нет. На вкладке «Генерация LCR»
  каждый защищённый юнит с новой площадью разрешается **отдельно**, с обязательным
  полем «Причина» — причина пишется в историю юнита и в аудит
  (`разрешены защищённые: N (причина: …)`). Старый параметр `overrideProtected`
  игнорируется.

### P1-3 — единый вход в планировки

- «Планировки и LCR» (`plan_master`) — единственный пункт меню; `project_layouts` /
  `leasing_layouts` — внутренние экраны, открываются из мастера (реестр файлов версий)
  и из рабочих столов проектов. Данные и раньше были едины (`CASE_LAYOUT_VERSIONS`),
  теперь един и маршрут.

### P1-5 — реестры модулей сведены

- В `validViews` добавлены отсутствовавшие `admin_modules`, `admin_system`, `v32_demand`.
- Каталог модулей (v3520) теперь досыпает свои view в `validViews` автоматически —
  новый модуль каталога не станет «невалидным view».
- В серверный список (`api/lib.php`) добавлен отсутствовавший `analytics_hub`.

### P1-6 — доменные сохранения и авто-слияние вместо «обновите страницу»

- Клиент отправляет в `state.php` только **изменённые домены** состояния
  (по-ключевой дифф против последней сверенной с сервером версии) — меньше трафика,
  меньше поверхность конфликта.
- Сервер сливает присланное по-ключево (`array_replace`): ключи, не вошедшие в запрос,
  сохраняют серверное значение. Старые клиенты шлют весь блоб — для них ничего не меняется.
- При конфликте ревизий клиент теперь **сам** подтягивает свежее состояние, возвращает
  поверх свои изменённые домены и сохраняет повторно («↻ Данные менялись параллельно —
  объединено и сохранено») вместо тоста «обновите страницу». Границы честные: конфликт
  внутри одного домена решается «последний пишущий побеждает», точечные правки юнитов
  дополнительно защищает серверный splice по `updatedAt` (из v4.32.x).

### P2 — заголовки безопасности

- `os/.htaccess`: добавлены **HSTS** (только по HTTPS, 1 год) и **CSP**
  (`'unsafe-inline'/'unsafe-eval'` вынужденные для однофайловой платформы; политика
  закрывает чужие домены скриптов, `form-action`, `base-uri`, встраивание в чужие фреймы).

## Проход по ролям и безопасности (по запросу)

- **Роли, браузерный прогон всех 10 демо-ролей** (`docs/qa/CASE_OS_v4.35.0_ROLE_ACCESS_QA.json`, 54/54):
  вход под каждой ролью; каждый пункт меню обязан проходить workspace-права роли;
  админ-экраны (`users`, `admin_modules`, `admin_system`) закрыты не-админам;
  внешний агент (AGX) не видит карту/бенчмаркинг; «только бренды» (BRJ) видит только «Базу брендов».
- **Исправлено:** правило «только бренды» терялось в групповом меню v3520 —
  BRJ видел лишние пункты. Восстановлено.
- **Статический аудит безопасности** (`docs/qa/CASE_OS_v4.35.0_SECURITY_STATIC_AUDIT.json`, 0 crit / 0 warn):
  сверка трёх реестров модулей, ролевые списки клиент↔сервер, авторизация всех
  API-эндпоинтов.
- **Закрыты 2 дыры:** `api/geo_collector.php` и `api/geo_seed_convert.php` были доступны
  из веба без авторизации (анонимный запуск долгого сбора с исходящими запросами и
  записью файлов в `data/`). Теперь оба — строго CLI (`403` на веб-запрос), как и
  соседние `cron_critical_dates.php` / `geo_master_install.php`.
- Проверено вручную: `setup.php` самозапирается после создания первого администратора;
  `geo_master.php` — `require_login` + whitelist выдаваемых файлов; fail-closed вход.
