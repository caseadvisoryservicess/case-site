# CASE OS v4.48.4 — детектор конфликтов CSS + кнопки на телефоне

Дата: 2026-07-25.

## 1. Новый инструмент: аудитор конфликтов CSS

Половина табличных багов v4.46–v4.48 была одной природы: правило одного модуля молча
перебивало правило другого, и найти это глазами почти невозможно (последний случай искали
три релиза). Теперь есть проверка, которая находит такое за минуту.

`docs/qa/tools/css_conflicts.js` поднимает платформу, обходит восемь разделов (стили
подгружаются лениво, при первом открытии экрана) и читает **живые** стили браузера — не
исходники. Ключевой принцип: конфликт засчитывается только если в реальной вёрстке есть
элемент, попадающий **под оба правила сразу**. Совпадения вида «оба про заголовки, но в
разных таблицах» отсеиваются, поэтому в отчёте нет мусора.

Проверка на себе: первым же пунктом инструмент выдал ровно тот баг, который в v4.48.3
искали вручную три релиза — правило `top:0!important` из старого UX-модуля против смещения
шапки из модуля таблиц, 44 элемента.

Что показал по текущей базе: 188 подтверждённых конфликтов с `!important`, из них 56
влияют на вёрстку (позиция, размеры), остальные косметические (цвет, шрифт). Чаще всего
спорят База брендов со своим UX-слоем и модуль таблиц с базовыми стилями. Это карта
техдолга — разбирать её нужно постепенно, отдельными правками.

## 2. Исправлено: мелкие кнопки в Базе брендов на телефоне

Первая находка инструмента, доведённая до исправления. В Базе брендов на мобильных
7 кнопок («+ Добавить бренд», «Импорт CSV/XLSX» и другие) были высотой 32 пикселя вместо
44, положенных для нажатия пальцем: старое правило раздела перебивало правило доступности.
В ЛСР проблемы не было. Проверено замером на экране 390×844 до и после — было 7 кнопок ниже
нормы, стало 0.

визуальная стабильность 9/9, синхронизация 12/12, надёжность 14/14, смоук 8/8, сценарии

кнопок на мобильной ширине.

Изменения только клиентские: `index.html`, `sw.js`, `v4450-ux-system.js`.
Серверные PHP не менялись.
