# CASE OS v4.42.1 — изменения

Дата: 2026-07-24. Ветка: `claude/new-session-2kq1ff`. Предыдущая версия: v4.42.0.

## Причина релиза: «данные не сохраняются» у сотрудников

Жалобы: у младшего админа брендов не сохранялись геоаналитика и база брендов; ранее у
администратора аренды «пропадали» данные ЛСР.

**Диагноз.** Сервер принимает изменения только тех разделов, которые включены в рабочей
области роли (защита P0-01 от записи в обход интерфейса). Сохранённые в базе шаблоны ролей
были записаны «снимками» эпохи узких умолчаний (v4.35) — без гео/брендов у BRJ, с урезанным
набором у других ролей. Итог: интерфейс раздел показывал, а сервер отклонял его сохранение
(гео — 403 в `geo_state.php`; остальные ключи тихо восстанавливались из старой копии,
`rejected_keys` в ответе никто не показывал). Данные «пропадали» молча.

## Исправления

1. **Миграция workspace schema 4421** (расширение миграции v4.42.0): сохранённый шаблон
   **каждой** роли одноразово дополняется её рекомендуемым набором разделов — это чинит и
   BRJ (гео/бренды/реестр), и администратора аренды (реестр/ЛСР/планировки), и любые другие
   обрезанные шаблоны. Срабатывает после входа администратора; после неё администратор
   может снова сузить набор — повторно миграция не вмешивается (`v3520-workspaces.js`).

2. **Отказ сервера больше не молчит.** Клиент читает `rejected_keys` из ответа `state.php`
   и показывает понятное предупреждение:
   - «⚠ НЕ сохранено: База брендов, Геоаналитика. Раздел не включён в вашу рабочую
     область — обратитесь к администратору» — при отказе по правам;
   - «↻ Помещения …: на сервере более свежая правка — ваша версия не записана.
     Обновите страницу» — при конфликте точечных правок юнитов (защита по updatedAt).
   Повторные отказы тех же разделов не спамят (одно предупреждение за сессию), длинные
   предупреждения держатся на экране 9 секунд (`index.html`).

Серверные файлы (`os/api/*`) не менялись — сервер уже возвращал `rejected_keys`.
