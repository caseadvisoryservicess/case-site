# CASE OS v4.32.7 — отчёт об исправлении sticky-шапки и прокрутки

## 1. Подтверждённые дефекты

В v4.32.6 пользователь воспроизвёл два связанных дефекта LCR:

1. При прокрутке вниз верхняя строка `БЮДЖЕТ / ФАКТ` оставалась видимой, а строка названий столбцов уходила под неё и частично обрезалась.
2. При прокрутке обратно вверх внутренний контейнер таблицы останавливался на первой строке и продолжал перехватывать колесо мыши. Страница не поднималась к заголовку проекта и основной панели CASE OS.

## 2. Корневая причина

Обычный CSS `position: sticky` находился внутри горизонтального overflow-контейнера таблицы. В браузере такой контейнер становится опорным блоком sticky-позиционирования, из-за чего:

- двухуровневые строки имели разные sticky-контексты;
- в реальном LCR нижняя строка могла уходить под верхнюю;
- sticky-шапка не могла надёжно учитывать верхнюю панель приложения;
- вложенный вертикальный scroller удерживал событие колеса на своей границе.

## 3. Реализованное решение

### 3.1 Единая закреплённая шапка

Для таблиц CASE Data Grid создаётся визуальная копия `colgroup + thead`, размещённая в фиксированном слое над таблицей. Исходный `thead` остаётся частью документа и определяет реальные размеры колонок, но перестаёт отдельно закрепляться.

Преимущества:

- обе строки шапки перемещаются как единый блок;
- ширины берутся из того же `colgroup`, что и тело таблицы;
- верхняя и нижняя строки не перекрывают друг друга;
- слой можно точно разместить под реальной верхней панелью;
- горизонтальное положение синхронизируется с таблицей.

### 3.2 Динамический offset верхней панели

Высота `.topbar` измеряется через `getBoundingClientRect()` и отслеживается `ResizeObserver`. Если верхняя панель меняет высоту, закреплённая шапка автоматически перемещается ниже неё.

### 3.3 Scroll handoff

На вертикально прокручиваемые контейнеры таблиц установлен обработчик границы:

- при `scrollTop = 0` и прокрутке вверх движение передаётся ближайшему родительскому scroller или странице;
- при нижней границе и прокрутке вниз движение также передаётся наружу;
- событие блокируется только когда передача действительно изменила внешний scroll;
- горизонтальные жесты и Ctrl/Meta-жесты не перехватываются.

### 3.4 Фильтры и горизонтальная прокрутка

- Кнопки фильтра в закреплённой копии проксируют действие в меню исходной колонки.
- Resize-ручки в копии не показываются, чтобы не создавать второй конфликтующий механизм изменения ширины.
- При изменении ширины, ререндере или resize окна копия строится заново из актуального `colgroup`.

## 4. Браузерная проверка

Проверка выполнена на настоящем DOM/CSS-движке Chromium через Chrome DevTools Protocol.

Протестированы размеры:

- 1024×640;
- 1366×768;
- 2048×1100.

Подтверждено:

- верх слоя совпадает с нижней границей topbar;
- строка групп и строка колонок прилегают без разрыва и перекрытия;
- высота двухуровневой шапки — 54 px в тестовой конфигурации;
- горизонтальное рассогласование исходной и закреплённой шапки — не более 1 px;
- `scrollLeft` синхронизируется;
- при возврате страницы наверх закреплённая копия скрывается;
- передача прокрутки вверх и вниз с границ внутреннего контейнера работает;
- фильтр из закреплённой шапки открывается для правильной LCR-колонки;
- при динамическом увеличении topbar до 86 px слой перемещается на 86 px.

Полный результат: `docs/qa/CASE_OS_v4.32.7_STICKY_SCROLL_BROWSER_TEST.json`.

## 5. Ограничения проверки

Проверка выполнена на браузерном fixture с реальным движком Chromium и структурой CASE Data Grid. Реальная авторизация, MySQL и данные production не изменялись. После установки требуется короткая визуальная staging-приёмка на вашем домене.
