# CASE OS v4.32.3 — отчёт об исправлениях

## Цель

Закрыть выявленные проблемы текущего рабочего контура без внедрения новой проектной модели доступа:

1. исчезновение правок LCR после визуально успешного сохранения;
2. неудобный и неодинаковый вид LCR, SCR и геоданных;
3. дублирующие фильтры;
4. зависающий редактор брокера;
5. ошибочная должность и чрезмерные права внешнего агента.

## Почему могли исчезать данные LCR

Ранее простая правка ячейки изменяла объект `U` в памяти, после чего отправлялся весь общий state платформы. Одновременно другая вкладка или сотрудник могли изменить любой другой раздел, увеличив серверную revision. В результате весь запрос получал конфликт либо автообновление успевало применить серверный state до завершения записи. Для пользователя это выглядело как «сохранилось, затем пропало».

## Новая схема сохранения

### Обычная правка

`Ячейка LCR → локальный объект → unit_patch.php → транзакция → только нужный юнит → новая revision`

### Структурная операция

`Создание/удаление/merge/split → diff массива юнитов → units_batch.php → одна транзакция → upsert/delete нужных юнитов`

Общий state больше не используется как основной способ записи этих операций. Локальный кэш остаётся страховкой на случай временной недоступности сервера.

## Табличный UX

Эталон — база брендов. Для LCR/SCR/геоданных сохранена отдельная бизнес-логика, но унифицированы:

- высота строк и отступы;
- фон и читаемость заголовков;
- Excel-фильтр в заголовке;
- сортировка;
- resize колонок;
- sticky headers;
- личные настройки;
- скрытие дублирующих filter rows;
- чипы активных фильтров.

## Редактор брокера

Select, который открывался от одиночного клика и оставался на экране, заменён явным popup-редактором. Он закрывается после выбора, клика вне, `Esc` или перехода к другому брокеру.

## Внешний агент

В v4.32.3 действует строгий режим:

- разрешена только отправка нового бренда или инвестора;
- существующие базы и контакты не раскрываются;
- LCR/SCR закрыты;
- generic API и whole-state запись запрещены;
- роль отображается как «Внешний агент».

Это временно безопаснее, чем показывать проектные данные до готовности v4.33.0 с назначением проекта и юнита.

## Ограничения тестирования

Выполнены синтаксические, статические, VM и HTTP-auth tests. Локальная браузерная навигация блокируется сообщением «Your organization doesn’t allow you to view this site», поэтому визуальная приёмка должна выполняться на staging-домене. PDO MySQL в CLI отсутствует, поэтому реальный commit/reload с рабочей БД также входит в staging checklist.
