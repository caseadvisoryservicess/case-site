# CASE OS v4.44.0 — изменения

Дата: 2026-07-24. Ветка: `claude/new-session-2kq1ff`. Предыдущая версия: v4.43.3.

## Найден и закрыт корень «данные не сохраняются» (ЛСР, геоданные)

Провёл сквозной аудит всех путей сохранения. Главная причина: **серверная сессия жила
1 час без запросов**. Сотрудник отходил (обед, встреча) — сессия умирала, и все
дальнейшие сохранения падали с «Не авторизован», при этом:
- очередь правок ЛСР бесконечно повторяла попытки с успокаивающим «повторим
  автоматически», а при перезагрузке страницы правки терялись;
- вход после истечения сессии затирал несохранённое свежими данными с сервера;
- гео-сохранения оставались только в локальной копии браузера — сам сотрудник видел
  свои данные (иллюзия «сохранено»), а коллеги — нет.

## Что сделано

1. **Сессия — 12 часов** вместо 1 часа (`api/lib.php`) — покрывает рабочий день.
2. **Keepalive**: пока сотрудник работает, клиент раз в 5 минут пингует сервер и держит
   сессию живой; если сервер всё же разлогинил — экран входа появляется сразу, а не
   в момент потери правок. Клиентский авто-выход при полном простое — через 2 часа.
3. **Вход после истечения сессии больше не теряет работу**: несохранённые правки
   остаются в очереди, на экране входа видно «несохранённые правки (N) будут
   отправлены автоматически», и после входа они **дозаливаются на сервер до** загрузки
   свежего состояния (раньше свежее состояние затирало их).
4. **Честные сообщения об ошибках** в очереди правок ЛСР:
   - нет прав (403): «⛔ Сервер отклонил правку … Правка НЕ сохранена — сообщите
     администратору» — без бесконечных бессмысленных повторов;
   - сессия истекла (401): «⚠ Сеанс истёк. Войдите заново — правки будут отправлены
     автоматически» (один раз, без спама);
   - нет связи: «повторим автоматически» — как раньше, с реальным повтором.
5. **Один горизонтальный ползунок** над таблицами вместо двух: тулбар «Таблица · N
   столбцов» вставал между полосой прокрутки и таблицей, из-за чего создавалась вторая
   полоса; дубликаты теперь убираются.
