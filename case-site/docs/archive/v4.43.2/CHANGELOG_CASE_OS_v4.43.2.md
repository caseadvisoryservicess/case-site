# CASE OS v4.43.2 — изменения

Дата: 2026-07-24. Ветка: `claude/new-session-2kq1ff`. Предыдущая версия: v4.43.1.

## 1. Геоаналитика: карта сама перелетает к проекту, отчёт можно переоткрыть

- При переходе «Карта объектов → Аналитика» карта теперь **сама перелетает к локации
  проекта** (зум 15) — раньше отчёт открывался, а карта оставалась где была, и проект
  приходилось искать вручную. Перелёт повторяется после отложенных перерисовок,
  которые раньше перебивали центрирование.
- **Отчёт можно переоткрыть**: в попапе маркера проекта (клик по объекту на карте)
  появилась кнопка «🎯 Отчёт по точке»; красный маркер отчёта тоже открывает его кликом.
- Техническая причина, почему перелёт не работал: в студии «map» — top-level `let`,
  а `window.map` — это DOM-элемент `<div id=map>` (named access), у него нет setView;
  вызов молча падал в try/catch.

## 2. «Лишняя полоска» на таблицах LCR устранена (+ найден шторм перерисовок)

По скриншоту «какая-то лишняя полоска на таблицах, и её можно схватить»:

- **Полоска** — это резайзеры столбцов, растянутые во всю высоту таблицы: правило
  прилипающей шапки ставило заголовкам `position:static!important`, отрывая якорь
  резайзеров (курсор «↔» ловился по всей высоте). Исправлено на `relative` —
  визуально то же, якорь сохраняется. Плюс страховка: осиротевшие резайзеры
  удаляются, `th` у улучшенных таблиц всегда позиционирован.
- Заодно найден и устранён **шторм перерисовок**: адаптивная панель действий
  (кнопки + «⋯ Ещё») зацикливалась — перенос кнопки менял ширину контейнера →
  пересчёт → перенос обратно, ~780 перестановок DOM в секунду на вкладке
  «План / бюджет». Из-за шторма табличный модуль (вечный дебаунс) вообще не успевал
  улучшать таблицы этой вкладки. Новый алгоритм: ширины кэшируются, состав считается
  математически, DOM меняется только при реальном изменении, возврат из «Ещё» — с
  запасом места (гистерезис). Замер: 782 → **0 мутаций в секунду**; таблица
  «План / бюджет» снова получает тулбар, ширины и фильтры.
- В табличный модуль добавлена защита от «голодания» дебаунса: даже при потоке
  мутаций улучшение выполняется не реже чем раз в 600 мс.
