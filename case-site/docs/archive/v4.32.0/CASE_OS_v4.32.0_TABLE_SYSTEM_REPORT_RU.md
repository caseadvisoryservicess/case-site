# CASE OS v4.32.0 — отчёт по единой табличной системе

## 1. Цель обновления

В предыдущей версии CASE OS разные разделы использовали разные подходы к таблицам. Это приводило к следующим проблемам:

- неодинаковый визуальный стиль;
- скрытая или непонятная сортировка;
- разные способы фильтрации;
- отсутствие resize у части таблиц;
- неудобное использование ширины экрана;
- несохранение личных настроек;
- риск дублирования бизнес-логики при попытке унифицировать интерфейс только через CSS.

В v4.32.0 создан общий слой **CASE Data Grid**, который унифицирует эргономику, сохраняя специальную бизнес-логику каждого раздела.

## 2. Архитектура решения

### 2.1. Progressive enhancement

Новый grid не переписывает все реестры в один монолитный компонент. Он улучшает существующую таблицу после её появления на странице.

Это уменьшает риск поломки:

- LCR и SCR;
- комиссионных расчётов;
- геоаналитики;
- редактирования брендов;
- специализированных кнопок и обработчиков;
- импортов и экспортов.

### 2.2. Специализированные и обычные таблицы

Таблицы разделены на два типа.

**Специализированные:** Brands, LCR, SCR, Geo. Их собственные сортировки, фильтры и бизнес-действия сохраняются.

**Обычные:** остальные рабочие реестры без полноценного табличного движка. Для них CASE Data Grid добавляет стандартные сортировку, фильтры, resize и управление видом.

### 2.3. Персональные настройки

Настройки таблицы хранятся по сочетанию:

- пользователь;
- раздел;
- идентификатор таблицы;
- структура колонок.

Если один сотрудник изменил ширину или скрыл колонку, интерфейс других сотрудников не меняется.

## 3. Общий стандарт таблиц

### Заголовок

- явный знак `↕`, когда сортировка доступна;
- `▲` или `▼`, когда сортировка активна;
- кнопка `▾` для фильтра;
- подсветка активного фильтра;
- resize-зона на границе столбца.

### Excel-подобный фильтр

Для текста:

- содержит;
- не содержит;
- начинается с;
- заканчивается на;
- равно;
- не равно;
- пусто / не пусто.

Для чисел:

- больше / больше или равно;
- меньше / меньше или равно;
- равно / не равно;
- между / вне диапазона;
- пусто / не пусто.

Также поддерживается:

- список уникальных значений;
- поиск внутри списка;
- выбрать всё;
- снять всё;
- объединение фильтров нескольких столбцов.

### Ширина колонок

- drag мышью;
- двойной клик — auto-fit;
- auto-fit всей таблицы;
- сохранение ширины персонально.

### Вид таблицы

Меню «Вид таблицы» предоставляет:

- комфортную плотность;
- компактную плотность;
- максимальную плотность;
- управление колонками;
- порядок колонок для совместимых таблиц;
- закрепление первых колонок;
- восстановление стандартного вида.

## 4. Логика по разделам

### 4.1. База брендов

Реализованы:

- фильтр по каждому рабочему столбцу;
- сортировка с явными индикаторами;
- числа и текст обрабатываются разными операторами;
- сохранение поисковой строки, быстрых chips, фильтров, сортировки, вида и page size;
- совместимость с режимами «Таблица / Список / Карточки»;
- сохранение текущей визуальной основы страницы.

### 4.2. LCR

Сохранена сложная двухуровневая структура:

- основные данные помещения;
- бюджет;
- факт;
- варианты;
- брокер;
- комментарии;
- статус.

Особенности:

- не добавляются дублирующие generic-фильтры;
- существующие `tblMenu` используются как Excel-меню;
- ширины старых resizer-ов считываются по устойчивому ID колонки;
- закрепляются первые рабочие колонки;
- фильтры и ширины сохраняются персонально;
- групповые заголовки не разрушаются перестановкой колонок.

### 4.3. SCR

SCR получает единый стандарт через общий `buildTable` и CASE Data Grid:

- сортировка;
- фильтры;
- resize;
- персональный вид;
- sticky header;
- единая визуальная сетка.

### 4.4. Геоаналитика

Geo Studio сохраняет собственный специализированный движок:

- фильтры по значениям;
- сортировка;
- редактирование ячеек;
- специальные наборы и статусы проверки.

При этом улучшено:

- использование полной ширины;
- personal key для ширин;
- personal key для фильтров и сортировки;
- согласованный дизайн с основной платформой;
- cache-busting v4.32.0.

### 4.5. Другие реестры

В исходниках обнаружено 98 шаблонов `<table>` в 15 файлах. Не все являются самостоятельными крупными реестрами: часть находится во вспомогательных карточках, отчётах или скрытых представлениях.

CASE Data Grid обрабатывает фактически отображённые таблицы с `thead` и `tbody`. Панель «Вид таблицы» добавляется только крупным рабочим таблицам, чтобы не перегружать маленькие служебные таблицы.

## 5. Производительность и безопасность логики

- используется debounce для повторной обработки DOM;
- MutationObserver реагирует только после изменений страницы;
- specialized filtering не дублируется;
- при изменении маршрута enhancer запускается повторно;
- grid-предпочтения не входят в корпоративный state;
- меню фильтра закрывается при переходе в другой раздел;
- минимум одна колонка всегда должна оставаться видимой;
- сложные групповые заголовки защищены от небезопасного reorder.

## 8. Заключение
