# CASE OS v4.32.0 — Changelog

Дата сборки: 23 июля 2026 г.

## Тип обновления

**Minor update**: единая табличная система для рабочих реестров CASE OS.

Версия повышена с `4.31.18` до `4.32.0`, поскольку изменение затрагивает общую инфраструктуру интерфейса, несколько крупных модулей и персональные настройки пользователей.

## Основные изменения

### 1. Новый общий табличный слой CASE Data Grid

Добавлен файл `os/v432-data-grid.js`.

Он автоматически улучшает рабочие таблицы платформы и предоставляет единый стандарт:

- закреплённые заголовки;
- явные индикаторы сортировки;
- Excel-подобные фильтры для обычных таблиц;
- видимые границы колонок;
- изменение ширины колонок мышью;
- двойной клик для автоматического подбора ширины;
- управление видимостью колонок;
- изменение порядка колонок там, где структура заголовка это допускает;
- закрепление первых видимых колонок;
- три режима плотности строк;
- восстановление стандартного вида;
- персональное сохранение настроек для каждого пользователя и каждой таблицы.

### 2. База брендов

База брендов сохранена как визуальный эталон и дополнена:

- постоянно видимыми индикаторами сортировки `↕`;
- активными индикаторами `▲/▼`;
- меню фильтра `▾` возле каждого рабочего столбца;
- текстовыми и числовыми условиями;
- выбором конкретных значений через checkbox;
- поиском по значениям столбца;
- изменением ширины колонок;
- личным сохранением поиска, фильтров, сортировки, вида и количества строк;
- закрытием меню фильтра при смене раздела и по клавише `Esc`.

### 3. LCR

Для таблицы LCR:

- сохранены групповые заголовки «Бюджет» и «Факт»;
- не добавляются дублирующие фильтры поверх существующей бизнес-логики;
- добавлены единые разделители и resize-механика;
- сохранены существующие Excel-подобные меню фильтрации;
- первые четыре рабочих столбца закрепляются;
- ширины колонок и фильтры сохраняются персонально;
- добавлено компактное меню «Вид таблицы»;
- поддержаны режимы плотности и автоматический подбор ширины.

Произвольная перестановка колонок LCR намеренно не включена, поскольку она может разрушить многострочные группы «Бюджет / Факт».

### 4. SCR

Таблица SCR переведена на общий визуальный и интерактивный стандарт:

- явная сортировка;
- меню фильтров;
- resize колонок;
- персональные настройки отображения;
- единая плотность, границы, hover и sticky header.

### 5. Геоаналитика

Для баз данных геоаналитики:

- таблица использует всю доступную ширину;
- сохранена собственная бизнес-логика геофильтров;
- добавлены единые визуальные границы и resize-механика;
- ширины, сортировка и фильтры сохраняются отдельно для каждого пользователя;
- сохранена связь специальных таблиц с функциями проверки и редактирования геоданных;
- обновлены cache-busting версии локальных скриптов Geo Studio.

### 6. Остальные таблицы платформы

Общий enhancer применяется к рабочим таблицам, которые фактически появляются в DOM и имеют корректные `thead` и `tbody`.

Для обычных таблиц без собственного специализированного движка добавляются:

- сортировка;
- текстовые и числовые фильтры;
- фильтр по уникальным значениям;
- resize;
- персональный вид таблицы.

Специализированная логика существующих таблиц не заменяется и не дублируется.

### 7. Персональные настройки

Персонально сохраняются:

- ширина колонок;
- скрытые колонки;
- порядок колонок для одноуровневых таблиц;
- закрепление колонок;
- плотность строк;
- сортировка и локальные фильтры;
- настройки базы брендов;
- настройки LCR;
- настройки таблиц геоаналитики.

Эти параметры не записываются в общий корпоративный state и не влияют на других сотрудников.

### 8. Версия и кэш

- `APP_VERSION` обновлён до `4.32.0`;
- Service Worker cache key: `case-os-v4320`;
- новый grid-файл включён в precache;
- все локальные скрипты основной платформы и Geo Studio используют `?v=4.32.0`;
- старые пустые checksum-файлы v4.29.x удалены из полного пакета.

## Ограничения приёмки

В текущей среде не выполнялись реальные production/staging проверки с MySQL и живой серверной авторизацией. Полноценный Geo Studio E2E в iframe ограничен политикой браузерной среды; его табличная логика проверена статически и отдельным browser fixture.

Перед production deployment необходимо пройти приложенный staging checklist.
