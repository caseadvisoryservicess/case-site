## A. Ключевые выводы и решения (10 пунктов)

1. **За порталом стоит полноценный ArcGIS Server 12 REST** - `https://db.ngis.uz/db/rest/services`. Не тайловый сервис, а **база с запросами**: доступны `/query`, фильтры SQL, агрегаты, GeoJSON. Это меняет оценку: данные не нужно «соскабливать» с карты, их можно забирать структурно.
2. **Доступ анонимный** - ни токена, ни ключа, CORS открыт. 27 сервисов, 26 из них с полным `Map,Query,Data`.
3. **Слой махаллей содержит 4 672 полигона по всем 14 регионам** - не только Ташкент. Получен полный реестр с кодами.
4. **Критичная находка:** у `MAHALLA_UZKAD_DB16/**MapServer**` стоит `capabilities: "Map"` - запросы закрыты. Но у сервиса-близнеца `**FeatureServer**` того же слоя доступ полный. Это почти наверняка ошибка конфигурации, а не решение. **Строить продукт на этой дыре нельзя** - см. риск R1.
5. **Три независимые системы кодов**, которые нужно связать в вашей модели данных: кадастровый префикс (`10`, `10:01`), SOATO (`1726`, `1726269`), UUID. Кросс-таблица собрана и сверена.
6. **Коммерческая недвижимость - 1 037 235 участков** (`NOTURAR`), из них **90 113 в г. Ташкент**. Это ядро для CASE Geo: у каждого участка кадастровый номер, махалля, категория и вид земель.
7. **Генплан Ташкента (7 569 зон)** несёт `funksiya`, `qavatlilik` (этажность), `qurilish_maydonining_yer_maydon` (застройка/участок), `seysmologik_zonasi`, `strategiya` (Консервация / Реконструкция / Реновация). Для девелоперского консалтинга это самый ценный слой портала.
8. **Налоговые зоны Ташкента (18 полигонов, 5 классов)** - готовый прокси для базовой стоимости земли по локации.
9. **Геометрия тяжёлая: 98 МБ на махалли в полной точности.** Серверная генерализация (`maxAllowableOffset=0.0002`) даёт **6 МБ при том же наборе** - 16-кратное сжатие. Для веб-карты использовать только генерализованную версию.
10. **Покрытие слоя махаллей - около половины фактического числа МФЙ в стране.** 4 672 против ~9-10 тыс. по официальным данным. Слой нельзя выдавать за полный реестр махаллей - см. риск R3.

## B. Текст для отчёта

Геопортал `open.ngis.uz` является витриной к промышленной ГИС-платформе Кадастрового агентства, построенной на ArcGIS Server. Портал не публикует данные в виде готовых наборов, однако его картографический backend `db.ngis.uz` открыт для анонимных структурированных запросов и поддерживает выборку по атрибутам, пространственные запросы, агрегацию и выгрузку в GeoJSON. Практически это означает, что административная сетка страны, кадастровый учёт земельных участков, градостроительное зонирование Ташкента и учёт многоквартирного жилого фонда доступны для машинного получения без ручного сбора.

Для задач CASE Geo наибольшую ценность представляют четыре группы слоёв. Первая - административная сетка (регионы, районы, махалли), которая задаёт единицы агрегации для любой рыночной аналитики. Вторая - кадастровый слой нежилых участков объёмом свыше миллиона записей, содержащий кадастровый номер, привязку к махалле и классификатор категории и вида земель; он позволяет строить карту коммерческого предложения и структуру землепользования по любому срезу. Третья - генеральный план Ташкента, содержащий разрешённую функцию, предельную этажность, коэффициент застройки и сейсмическую зону по каждому контуру; этот слой напрямую применим в предпроектном анализе площадок и в проверке реализуемости девелоперских сценариев. Четвёртая - налоговое зонирование города, дающее нормативную дифференциацию локаций.

Существенным ограничением является полнота. Слой махаллей покрывает 4 672 единицы при фактическом числе МФЙ в республике порядка девяти-десяти тысяч, а в кадастровом слое нежилых участков 229 011 записей (22%) не имеют заполненного классификатора земель. Таким образом, данные портала пригодны как опорный геометрический и кодовый каркас, но не как исчерпывающий источник; для коммерческого продукта их следует рассматривать как первый слой, требующий верификации и дополнения.

Отдельно следует зафиксировать вопрос правового режима. Портал является публичным и не требует авторизации, однако публичная доступность не равнозначна разрешению на коммерческое переиспользование. До включения этих данных в платный продукт необходимо получить от Кадастрового агентства официальное подтверждение условий использования либо заключить соглашение о предоставлении данных.

### C.2 Три системы кодов - как связывать

| Уровень | Кадастровый префикс | SOATO | UUID | Пример |
|---|---|---|---|---|
| Регион | `10` … `23` | `1703` … `1735` | `region uuid` | `10` = `1726` = Toshkent shahri |
| Район | `10:01` | `1726269` | `district uuid` | `10:09` = `1726269` Mirzo Ulug'bek (сверено) |
| Махалля | - | - | `mahalla_code` (UUID) | `f5a02e57-…` |
| Махалля (номер) | - | `cadastral_number` = SOATO района + 3 цифры | - | `1712216006` = район `1712216` + `006` |
| Участок | `10:08:42:03:02:0197` | `soato_district` | `sp_id` / `sp_uid` | регион:район:массив:квартал:блок:участок |

**Ключ связи:** участок → махалля идёт **только через `mahalla_code` (UUID)**, не через кадастровый номер - форматы номеров у участка и махалли разные.

**Кросс-таблица префикс↔SOATO построена и сверена 1:1** - файл `district_crosswalk.csv`, 206 строк, 175 районов + 31 город, без дублей с обеих сторон. Правило типа: в SOATO пятый знак `2` = туман, `4` = шахар; при сопоставлении по названию тип обязателен, иначе одноимённые район и город схлопываются (`Buxoro tumani` ≠ `Buxoro shahri`).

**Важно: названия районов в двух слоях не совпадают в 25 случаях из 206** - `shahar` против `shahri`, `Marxamat` против `Marhamat` и т.п. **Join по названию делать нельзя**, только через готовую кросс-таблицу.

## E. Что нужно от вас, чтобы двигаться дальше

1. **Решение по R2** - идём ли к Кадастр агентлиги за официальным доступом. Это определяет, легальна ли монетизация. Без ответа не рекомендую включать эти данные в платный тариф.
2. **Целевая СУБД платформы** - PostGIS? Тогда сразу гружу через `--postgis`, без промежуточных файлов.
3. **Приоритет городов** - только Ташкент на MVP или сразу Самарканд/Бухара/Нукус. От этого зависит объём шага 6.
4. **Официальный перечень МФЙ** для сверки покрытия (R3) - если есть контакт в Махалла ва оила вазирлиги.
5. **Нужны ли исторические срезы** - в данных есть `create_at` / `modify_at` / `version_life`, инкрементальная синхронизация возможна, но требует расписания.

## Приложение: как запустить

```bash
# посмотреть все слои с живыми счётчиками
python3 ngis_etl.py --list

# схема полей любого слоя
python3 ngis_etl.py --layer NOTURAR --schema

# махалли всей республики, веб-версия (~6 МБ)
python3 ngis_etl.py --layer MAHALLA --simplify 0.0002 --out mahalla.geojson

# реестр махаллей без геометрии (коды)
python3 ngis_etl.py --layer MAHALLA --no-geometry --out mahalla.csv

# коммерческие участки Ташкента
python3 ngis_etl.py --layer NOTURAR --where "soato_region='1726'" --out tashkent_comm.geojson

# сразу в PostGIS
python3 ngis_etl.py --layer GENPLAN --postgis "postgresql://user:pw@host/casegeo"
```

Без Python - открыть `open.ngis.uz`, F12 → Console, вставить `browser_console_download.js`, запускать вызовы из комментария внизу файла.

**Полезные SQL-фильтры:** `soato_region='1726'` (Ташкент), `soato_district='1726269'` (Мирзо Улугбек), `land_fund_type='006003001005'` (зоны предпринимательства), `land_fund_category='006003'` (промышленность/транспорт/связь).
