# CASE OS — автобэкап БД и cron-задачи на DirectAdmin (пошагово)

_Для хостинга caseadvisory.uz (DirectAdmin, `caseadvisory.uz:2222`, логин `wwwcasea`)._

Механизм уже встроен в платформу (`os/api/backup.php`): полный SQL-дамп всех таблиц,
сжатие в `.sql.gz`, папка `os/sql/backups/`, автоудаление копий старше 30 дней.
Восстановление — только администратором из интерфейса (перед восстановлением
автоматически делается защитный снимок текущей базы).

Осталось один раз настроить запуск по расписанию.

## Шаг 1. Придумайте секретный токен

Любая длинная случайная строка (40+ символов), например сгенерируйте на своём
компьютере: `openssl rand -hex 24` — или просто наберите вручную длинную
бессмысленную строку. Дальше она называется `ВАШ_ТОКЕН`.

## Шаг 2. Впишите токен в config.php на сервере

1. DirectAdmin → **Менеджер файлов** → `domains/caseadvisory.uz/public_html/os/api/`.
2. Откройте `config.php` на редактирование.
3. Найдите строку `'backup_token' => '...'` (если её нет — добавьте в массив настроек):
   ```php
   'backup_token' => 'ВАШ_ТОКЕН',
   ```
4. Сохраните файл.

## Шаг 3. Проверьте руками, что бэкап создаётся

Откройте в браузере (одной строкой):

```
https://caseadvisory.uz/os/api/backup.php?token=ВАШ_ТОКЕН
```

Должен прийти ответ `{"ok":true,"file":"caseos_2026-07-24_HHMMSS.sql.gz",...}`,
а в `os/sql/backups/` появиться файл. Если ответ «Только администратор» — токен в
config.php не совпадает с токеном в ссылке.

## Шаг 4. Добавьте cron-задачу

DirectAdmin → **Дополнительные возможности → Cron Jobs** (Задания Cron) → Create Cron Job:

- **Минуты:** `0` · **Часы:** `3` · **Дни/месяцы/дни недели:** `*` (ежедневно в 03:00)
- **Команда:**
  ```
  curl -s "https://caseadvisory.uz/os/api/backup.php?token=ВАШ_ТОКЕН" >/dev/null 2>&1
  ```
  Если `curl` на хостинге недоступен, вариант с wget:
  ```
  wget -q -O /dev/null "https://caseadvisory.uz/os/api/backup.php?token=ВАШ_ТОКЕН"
  ```

Готово: каждую ночь в 03:00 создаётся копия, старше 30 дней — удаляются сами.

## Шаг 5 (настоятельно рекомендуется). Копия вне сервера

Раз в месяц скачивайте свежий `.sql.gz` себе (интерфейс платформы:
Администрирование → резервные копии → «Скачать», либо из `os/sql/backups/` через
Менеджер файлов) — бэкап на том же сервере не защищает от потери самого сервера.

## Бонус: уведомления о критичных датах (тот же экран Cron Jobs)

Скрипт `os/api/cron_critical_dates.php` шлёт письма о приближающихся датах
(окончания броней, дедлайны). Ему нужны:

1. Заполненный блок `'smtp' => [...]` в `os/api/config.php` (хост/порт/логин/пароль
   почты — берутся у хостинга или почтового сервиса).
2. Файл получателей `os/api/notify_recipients.php` (образец —
   `notify_recipients.sample.php` рядом: скопируйте и впишите адреса).
3. Cron-задача (запуск по будням в 08:00; скрипт принимает ТОЛЬКО CLI-запуск):
   ```
   /usr/local/bin/php /home/wwwcasea/domains/caseadvisory.uz/public_html/os/api/cron_critical_dates.php
   ```
   Точный путь к PHP и к домашней папке можно уточнить у поддержки хостинга;
   в DirectAdmin путь к php обычно `/usr/local/bin/php`.

## Что где лежит (памятка)

| Что | Где |
|---|---|
| Скрипт бэкапа | `os/api/backup.php` (веб, `?token=` только на создание копии) |
| Папка копий | `os/sql/backups/*.sql.gz` (закрыта от веба через `.htaccess`) |
| Восстановление | интерфейс платформы, только админ, POST+CSRF |
| Уведомления о датах | `os/api/cron_critical_dates.php` (только CLI) |
| Гео-сборщик | `os/api/geo_collector.php` (только CLI, запуск вручную при необходимости) |
