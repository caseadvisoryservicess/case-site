# Geo Platform MVP: бизнес-центры Ташкента одним HTML-файлом

Файл: `docs/standalone/CASE_Geo_Platform_MVP.html` (около 720 КБ). Открывается двойным щелчком
с диска, без сервера и без входа. Из сети нужны только тайлы OpenStreetMap; без интернета
работает всё, кроме подложки карты.

Это не замена студии CASE Geo Analytics (`CASE_Geo_Analytics.html`), а второй, более
узкий продукт по брифу `geoanalytics_html_mvp_master_prompt.md`: структурированная база
бизнес-центров с происхождением каждого поля, честная аналитика и детерминированный
Geo AI без внешней модели.

## 1. Как собрать и проверить

```
node docs/qa/tools/build_geo_mvp.js
NODE_PATH=<путь к playwright-core> node docs/qa/tools/v4733_geo_mvp.js
```

Сборщик берёт шаблон `docs/standalone/src/geo_mvp.template.html`, встраивает Leaflet
1.9.4 и Leaflet.markercluster из `os/`, данные из `docs/standalone/data/geo_mvp_data.json`
и пишет готовый файл. Шаблон и готовый файл лежат в разных папках, чтобы сборка не
затирала исходник. Тест открывает готовый файл по `file://`, блокирует сеть и прогоняет
десять пользовательских сценариев и восемь тестов Geo AI из брифа плюс редактор данных,
localStorage, RU-интерфейс и телефонную вёрстку (55 проверок).

## 2. Спецификация в двух абзацах (как понята из брифа)

Одностраничная гео-платформа для коммерческой недвижимости, сначала только бизнес-центры
Ташкента. Шапка с нейтральным именем продукта, селекторами города и типа (пока по одному
значению), глобальным поиском, кнопками «Analytics», «Geo AI» и бейджем качества данных.
Слева фильтры, в центре карта Leaflet на OSM с кластеризацией и маркерами по классу,
слоем районов, кнопками «вписать», «сброс», «во весь экран». Справа выдвижная панель с
вкладками «Объект», «Сравнение», «Локация», «Слои ИИ». Снизу панель аналитики.

Данные: одна запись на здание со схемой property/v1, у каждого ключевого поля свой блок
источника (источник, ссылка, даты сбора и проверки, метод, уверенность High/Medium/Low/
Unknown, примечание). Ничего не выдумывается: пропуск показывается как n/a, средние
считаются только по известным значениям и всегда со знаменателем. Geo AI разбирает
запрос детерминированно, вызывает инструменты платформы и отвечает шестью блоками:
ответ, анализ, действия на карте, покрытие данных, ограничения, источники.

## 3. Противоречия и риски брифа (шаг 2 брифа) и что решено

| Пункт брифа | Проблема | Решение в MVP |
|---|---|---|
| «Только реальные данные, ничего не выдумывать» и одновременно сценарии «здания больше 5 000 м²», «три крупнейших по GLA», «заполняемость» | В доступной базе CASE у 148 реальных БЦ нет ни одной GLA, заполняемости и свободной площади; класс известен у 16, ставка у 16 | Реальные записи оставлены как есть (пропуски видны). Добавлены 6 записей с префиксом DEMO и полем `meta.demo=true`, чтобы сценарии по площади работали. Они помечены на карте (пунктирная рамка), в карточке, в списке, в ответах ИИ, и выключаются одним переключателем |
| Слои метро, дорог, конкурентов «из исследований CASE» | В автономном файле без сервера нет доступа к Overpass и к исследованиям | Слоёв метро и дорог нет, это сказано в ограничениях. Конкурентный набор считается из самой базы (расстояние, класс, размер) |
| «Ссылка на источник» для каждого поля | У выгрузки из карт-сервисов ссылки на карточку нет | Поле `url` пустое, показан источник и метод («map service»), кнопка «Открыть источник» появляется только если ссылка есть |
| Оценка «уверенности» по записи | В брифе не сказано, как сводить уверенность полей в одну | Правило: уверенность записи = худшая из уверенностей координат и заполненных ключевых полей (класс, GLA, ставка) |
| «Устаревшие данные» без порога | Порог не задан | 180 дней от последней проверки или сбора; «следующая проверка» = `meta.nextRefresh` или последняя проверка + 180 дней |
| Geo AI «с session context» и одновременно «каждый запрос воспроизводим» | Один и тот же вопрос даёт разный результат в зависимости от прошлых фильтров | Правило: запрос со словом «only/только/из них» сужает прошлый результат; любой другой запрос с фильтрами начинает с чистого состояния (переключатель DEMO сохраняется). Агрегаты («GLA по районам класса A») считаются на свежем фильтре, если в вопросе названы класс или район, иначе по текущей выборке, и ответ говорит, какая выборка |
| Название ZAKY | Бриф просит нейтральное имя | «Geo Platform MVP» |
| Языки EN/RU/UZ | Узбекского словаря в брифе и в базе нет | EN основной, RU полный, UZ показан в списке как «скоро» и выключен |
| Ориентир «Tashkent City» для сценариев | В базе нет объекта с таким именем | Сценарии проверяются на Trilliant и Nova Plaza; ИИ находит объект по значимым словам названия |
| Плотность сотрудников, проходимость | Данных нет | Отдельный интент «недоступно»: честный отказ без оценки из несвязанных переменных |

## 4. Что реализовано

- Шапка: имя продукта, город, тип, глобальный поиск (имя, адрес, район, арендатор) с выпадающим списком и Enter, «Analytics», «Geo AI», бейдж «N записей · D demo · данные обновлены …», переключатель языка, редактор данных.
- Фильтры: название, район, класс (включая «неизвестно»), статус, уверенность, DEMO, GLA, ставка, заполняемость, свободная площадь, «парковка известна», инфраструктура, «только неполные», «только устаревшие». Счётчик «N properties found · of M records · описание фильтра». Панель сворачивается.
- Карта: OSM, кластеризация, маркеры по классу с буквой класса и серым «?» для неизвестного, пунктир для DEMO, подсказка при наведении, выделение выбранного, «вписать результаты», «сброс», «во весь экран», слой районов (12 полигонов из локального GeoJSON, подписи на текущем языке), легенда.
- Список «Карта + список»: карточки с классом, районом, GLA, ставкой, заполняемостью, статусом и уверенностью, переключатель сравнения; отметки обновляются на месте без потери прокрутки.
- Карточка объекта: заголовок, адрес, бейджи (класс, статус, уверенность, «устарело», «нет ключевых данных», DEMO), действия «Сравнить», «Анализ локации», «Спросить ИИ», «Копировать координаты», «Открыть источник» (если есть ссылка), «Править»; секции метрики, коммерческие условия, арендаторы, инфраструктура, локация (координаты, три ближайших БЦ), качество (проверено, следующая проверка, статус), источники (сгруппированы по источнику с перечнем полей). У каждой метрики под числом источник, дата и уверенность.
- Аналитика: 7 карточек (число, известная GLA, средняя и медианная ставка, известная свободная площадь, средняя заполняемость, действующие/пайплайн) и 4 SVG-графика (по районам, по классам, распределение ставок и GLA). Каждая карточка со знаменателем «Based on n of m …»; меньше трёх известных значений → «Insufficient verified data». Реагирует на фильтры и на фильтры, поставленные ИИ.
- Сравнение 2..4: таблица без победителя, пропуски как n/a, удаление из таблицы, лимит 4 с уведомлением.
- Анализ локации: круги 1/3/5 км, число БЦ в каждом радиусе, средняя ставка и известная GLA в 3 км со знаменателями, состав по классам, примечание о расчёте по прямой; предлагаемый конкурентный набор (расстояние, класс, размер, с причинами), правится галочками, «слой из набора», «сравнить набор».
- Слои ИИ: список с числом записей, критерием, цветом; показать/скрыть, переименовать, удалить. Слои трёх видов: фильтр (кольца вокруг объектов), радиус (круг + кольца), район (заливка полигона).
- Geo AI: детерминированный разбор на EN и RU (класс, район, GLA, свободная площадь, ставка, статус, радиус, объект по названию), интенты filter, select, radius, competitors, compare, supplyByDistrict, glaByDistrict, rentByDistrict, quality (уверенность, устаревшие N месяцев, неполные), clear, unavailable, unknown; реестр инструментов `Tools` (searchProperties, applyFilters, clearFilters, selectProperty, zoomToProperty, getNearby, createRadius, createLayer, removeLayer, clearLayers, compareProperties, showCompetitors, aggregateByDistrict, aggregateByClass, calculateMetric, getDataCoverage, getSources, showDataQuality, exportResults); индикация шагов; журнал сеанса в localStorage; кнопка «Очистить сеанс»; восемь подсказок из брифа; абстракция `AI.providers` для будущей модели (ей достаточно выдавать такой же план {intent, args}).
- Редактор данных (локальный прототип): новый объект, правка, удаление с подтверждением, координаты кликом по карте, все ключевые поля, инфраструктура, арендаторы построчно, DEMO-флаг, дата следующей проверки, блоки источника для координат, класса, GLA, ставки, заполняемости; Export JSON, Import JSON (массив или {properties:[…]}, валидация id/name/lat/lng), Reset demo data; всё в localStorage, переживает перезагрузку.
- Локализация: EN и RU полностью (интерфейс, подписи районов, ответы ИИ, подсказки); выбор запоминается.
- Адаптивность: до 820 px левая панель, список, карточка, ИИ и редактор становятся выдвижными панелями, внизу панель «Карта · Список · Фильтры · Geo AI · Аналитика», горизонтальной прокрутки нет.

## 5. Ограничения

Данные: у реальных записей нет GLA, GBA, этажности, парковки, заполняемости, свободной
площади и арендаторов; класс у 16 из 148, ставка у 16; ссылок на карточки источника нет.
Все сценарии по площади и заполняемости показывают в основном DEMO-записи, и ответы ИИ об
этом говорят. Ставки asking, не достигнутые. Ни одна запись не проверена в поле
(`verificationStatus: needs_review`).

Функции: нет изохрон и времени в пути (только прямая линия); нет слоёв метро, дорог,
жилья, конкурентов из исследований; нет фото; нет ролей и входа (редактор открыт всем, кто
открыл файл); импорт заменяет набор целиком, а не сливает; экспорт только JSON; узбекский
язык не готов; ответ ИИ не экспортируется в PDF.

Geo AI: понимает ограниченный набор формулировок (см. подсказки); объект в запросе ищется
по значимым словам названия, редкие короткие названия (RS, TUT) по одному слову не
находятся; свободный текст вне этих интентов даёт честное «не понял» с примерами.

## 6. Что улучшить дальше

1. Заполнить GLA, этажность, парковку и арендаторов хотя бы для 30 БЦ классов A/A+ с ссылками на источник, после чего убрать DEMO-записи.
2. Поле «проверено» и статус QC вести в редакторе с историей изменений (кто, когда).
3. Слои контекста: метро, магистрали, плотность жилья из мастер-геобазы CASE OS (собираются той же сборкой, что `CASE_Geo_Analytics.html`).
4. Изохроны пешком и на авто через OSRM (уже есть в студии), с честной подписью источника.
5. Подключить локальную модель (Ollama, OpenAI-совместимый API) как второй провайдер `AI.providers`, который выдаёт тот же план {intent, args}; числа по-прежнему считают инструменты.
6. Экспорт ответа ИИ и сравнения в PDF/Excel через модуль выгрузки студии.
7. Узбекский словарь интерфейса.

## 7. Схема данных property/v1

| Поле | Тип | Смысл |
|---|---|---|
| id, name, altName | string | идентификатор, название, прежнее название |
| address, district, districtRu | string | адрес, район (EN-ключ из 12), русское имя района |
| lat, lng | number | координаты WGS84 |
| class | 'A+' 'A' 'B+' 'B' 'C' или null | класс офиса |
| status | operating, under_construction, planned, renovation, unknown | статус |
| yearOpened, yearRenovated, floors | number или null | год, этажность |
| gba, gla, floorPlate | number или null | площади, м² |
| parkingSpaces, parkingRatio | number или null | парковка |
| developer, owner, operator | string | участники |
| rent, currency, rentUnit, serviceCharge, vat | number/string | ставка asking USD/м²/мес, эксплуатационные, НДС |
| occupancy, vacancy | 0..1 или null | доли |
| availableArea, minUnit, leaseTerms | number/string | свободная площадь, минимальный блок, условия |
| tenants | [{name, category, area, floor}] | арендаторы |
| amenities | [string] | инфраструктура из словаря |
| evidence | {поле: {source, url, collected, verified, method, confidence, note}} | происхождение поля (coordinates, class, gla, rent, occupancy, name, status и др.) |
| meta | {demo, collector, timestamp, verificationStatus, qcStatus, nextRefresh, note, masterId, dataConfidence, sourceCount, possibleDuplicate} | служебные |

Пропуск всегда `null`, никогда 0 или пустая строка для чисел.

## 8. Формулы и правила пропусков

- Уверенность записи = максимум по «худшести» из уверенности координат и уверенности заполненных полей класс, GLA, ставка (high < medium < low < unknown).
- «Нет ключевых данных» = отсутствует хотя бы одно из: класс, GLA, ставка.
- Последняя проверка = самая поздняя дата `verified` или `collected` среди всех источников, иначе `meta.timestamp`. Устарело = больше 180 дней от неё. Следующая проверка = `meta.nextRefresh`, иначе последняя проверка + 180 дней.
- Числовой фильтр (GLA, ставка, заполняемость, свободная площадь) никогда не пропускает запись с пропуском: здание с неизвестной GLA не попадает в «больше 5 000 м²».
- Среднее и медиана считаются по записям с известным значением; знаменатель показан; при менее чем трёх известных значениях выводится «Insufficient verified data».
- Расстояния по формуле гаверсинуса, радиусы 1/3/5 км по прямой.
- Конкурентный набор: кандидаты в радиусе; очки: расстояние до 1,5 км (+1), тот же класс (+2), соседний класс (+1), GLA в пределах 0,5..2 от объекта (+1); в набор попадают кандидаты с 2+ очками (до 6), а если их меньше трёх, то пять ближайших; причины показаны у каждого.
- Аналитика по районам считает «известно / всего» на район; район без известных значений подписан «недостаточно данных», а не нулём.

## 9. Архитектура Geo AI

Запрос → `AI.parse(text, ctx)` (регулярные выражения EN/RU, словарь районов с синонимами,
поиск объекта по словам названия) → план `{intent, args}` → `AI.execute(plan)` вызывает
функции реестра `Tools` над состоянием платформы (никаких эмулированных кликов) →
структурированный ответ (Answer, Analysis, Map actions, Data coverage, Confidence /
limitations, Sources) → журнал сеанса. Провайдер выбирается в `AI.provider`; локальная
модель должна вернуть тот же план, чтобы числа и слои считались только инструментами.
